# AHC050

[公式問題](https://atcoder.jp/contests/ahc050/tasks/ahc050_a) /
[公式 Rust ジェネレータ・ビジュアライザ](https://img.atcoder.jp/ahc050/k1BmZE1o.zip)。
滑走するロボットを押しつぶさないよう、岩を置く順を選びます。

## 次の死亡確率だけを見る基準と、3 手先の比較

開始位置の一様分布から、各生存確率を 4 方向の停止点へ移し、
次に岩を置く点の確率をそこから引きます。
基準版は滑走後の確率が最低の点へ順に岩を置きます。
候補版は確率の小さい最大 14 点を候補とし、そこに岩を置いて
次の岩を貪欲に選び、さらに 1 回分の遷移も見ます。
1、2、3 手目の死亡確率をそれぞれ 3、2、1 倍して足し、
最小にします。同じなら比較後の生存質量が少数の点に集まる案を
選びます。実際の評価は全手の生存確率の合計です。
追加計算を行うため、等実行時間の比較ではありません。

| 新規独立シード | 貪欲 | 3 手先を見る | 先読みの勝ち |
|---|---:|---:|---:|
| 開発 10 件 | 9,156,386 | 9,704,786 | 10/10 |
| 凍結後・未調整 20 件 | 18,411,827 | 19,455,464 | 20/20 |

未調整では 5.67% 改善。全 60 実行で合法、公式 `vis`、
行列の連続区間を足す独立検査、C++ の得点が一致しました。
候補の最大壁時間は 0.220 秒未満（CPU 7 固定）。
既定は両方を作って高得点な方を出します。先読みには 1.7 秒の
内部期限があり、未完成なら先に作った貪欲解を返します。
`-DAHC050_GREEDY_ONLY` と `-DAHC050_LOOKAHEAD_ONLY` が各比較版です。

## 本番比較

絶対点は `round(10^6×期待獲得金/(N²−M−1))` の最大化。
40×40、2 秒・1,024 MiB。コンテスト中の 150 件の和で、本番後の
システムテストはなく、1 件でも不正・時間超過なら全体が 0 点です。
[公式結果](https://atcoder.jp/contests/ahc050/results/json)で 1 位は
yosupo と確認しましたが、点数は載っていません。
[公式順位表](https://atcoder.jp/contests/ahc050/standings/json)は
ログインが必要で、[得点 CSV](https://img.atcoder.jp/ahc_standings/ahc050/result.csv)
と [入力対応表](https://img.atcoder.jp/ahc_standings/ahc050/input.csv)
は HTTP 403。公式ツール付属のシードはデモ 100 件で、150 件の
本番との対応が不明です。これらと重複しない新規シードを使いました。
本番の点数・入力が揃わないので **未判定** です。
外部の解説、公式サンプルの解法や他の提出は使っていません。

## 再現とライブラリ

公式 zip SHA-256:
`86f8e49153c72e20637cc166419e3eae929324ffb515c3a0c8bd25e219a11692`。
`cargo build --release --locked --bin gen --bin vis` でビルドします。
Linux で Fontconfig の開発メタデータがなく実行用ライブラリが
使える場合、この検証では `RUST_FONTCONFIG_DLOPEN=1` を付け、
公式コードを変更せずにビルドしました。

```bash
bash problems/ahc050/run.sh build/ahc050 "$gen" "$vis" 7
```

C++23 単一ファイルで 963,230 点を再現。
既存 [ProbabilityMoveDP](../../library/probability-move-dp.hpp) は
固定の成功先とその場滞在のモデルなので、4 方向の停止点が壁の更新で
変わる盤面には直接使えません。
[`OrthogonalSlideGrid`](../../library/orthogonal-slide-grid.hpp) に
更新と質量の再配分を分けました。
[使用例](../../examples/orthogonal_slide_grid_usage.cpp) と
[12,500 回の壁更新の愚直比較](../../tests/orthogonal_slide_grid_test.cpp)。
次は固定した後半の得点が生存分布に対して線形であることを使い、
隣接する岩の順を交換した時の全体点を短時間で正確に比べます。

## 残りの全手の期待値で隣接スワップを選ぶ（採用）

確定した配置列の後ろから、各位置で生存している時の将来の
獲得金を計算します。手 t の値は 4 方向に対して、
次の岩に当たれば 0、当たらなければ「1 + 到着点の手 t+1 の値」
の平均です。隣接する二つの岩を交換しても、2 手後の盤面は同じ。
そこで、変わった 2 手の獲得金に、2 手後の生存分布と
同じ盤面の将来値ベクトルの内積を足して、全手の差を正確に比べます。

どちらも初回の既定と同じ配置列で開始し、重ならない隣接ペアの
偶数・奇数開始位置を交互に、最大 5 回走査します。
対照は 2 手分の期待値だけで採否を判断します。同じ提案回数と
1.7 秒の締切を使い、各版とも得点が悪化した完成案は採用しません。
追加処理の計算内容は違うため、計測壁時間は同じとは限りません。

| 新規独立シード | 2 手だけの交換 | 全後半を評価 | 全後半版の勝ち |
|---|---:|---:|---:|
| 開発 10 件 | 9,760,937 | 9,792,548 | 10/10 |
| 凍結後・未調整 20 件 | 19,401,191 | 19,486,823 | 20/20 |

未調整で 0.44% 改善し、全 60 実行が合法、公式と独立再生が一致。
交換前の計測は開発 9,760,937、未調整 19,401,186（C++ の値）で、
2 手だけの更新は合計 5 点の改善に留まりました。
CPU 7 固定の最大壁時間 0.437 秒未満、C++23 単一ファイルも
961,543 点でした。小盤面 250 試行では、採否のたびに
全手を素朴に再生する検査と期待値が一致しました。

既定で全後半版を利用し、`-DAHC050_INITIAL_ROUTE_ONLY` で追加前、
`-DAHC050_LOCAL_SWAP` で局所評価の対照を再現できます。
本番入力は使っていません。次は 3〜4 手の区間内の並べ替えを試し、
区間終了時の盤面が同じという性質で全得点を正確に比較します。

```bash
bash problems/ahc050/run_suffix_swap.sh build/ahc050-adjoint "$gen" "$vis" 7
```
