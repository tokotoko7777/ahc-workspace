# AHC041

[公式問題](https://atcoder.jp/contests/ahc041/tasks/ahc041_a) /
[公式 Rust ジェネレータ・ビジュアライザ](https://img.atcoder.jp/ahc041/m0Bwp9WL.zip)。
指定のグラフから高さ上限内の森を選び、重い頂点を深くします。

## 同じ時間で、再構築と部分木の付け替えを比較

基準は頂点の重みに乱数を加えて親候補の優先順を作り、深さ制限付き
DFS で森を構築します。候補も最初の最大 13 回は同じ再構築を使いますが、
その最良解から、頂点を子孫ごと隣接する別の頂点の下へ移すか、
根として切り離す焼きなましを行います。自己参照・循環・最大深さを
先に検査し、合法な場合だけ差分点を使います。
部分木内の深さ差は一定なので、得点差は部分木の重み和 × 深さ差です。
両版の内部計測予算は 140 ms、最良の合法解を保持します。

| 新規独立生成 | 再構築のみ | 部分木付け替え | 付け替えの勝ち |
|---|---:|---:|---:|
| 開発 12 件 | 5,765,303 | 5,951,622 | 12/12 |
| 凍結後・未調整 24 件 | 11,534,138 | 11,915,002 | 24/24 |

未調整で 3.30% 改善し、作業ブランチの既定としました。
再構築のみは `-DAHC041_RESTARTS_ONLY` で再現。
全 72 実行で親辺・深さを独立再生し、公式 `vis`・C++ と点数一致。
CPU 7 固定の最大壁時間は 0.191 秒未満。
C++23 単一ファイルを別に検証し 497,564 点で合法でした。
壁時計で反復回数を止めるため、同じ入力でも得点が変わり得ます。

## 本番の物差し

絶対点 `1+Σ A_v×(depth_v+1)` の最大化。コンテスト中の 150 ケースの
合計で、終了後のシステムテストはありません。一件でも不正または
時間超過なら提出全体が 0 点です。制限は 2 秒・1,024 MiB。

[公式結果](https://atcoder.jp/contests/ahc041/results/json) で 1 位は
hitonanode と確認しましたが、得点は掲載されていません。
[順位表](https://atcoder.jp/contests/ahc041/standings/json) は
ログインが必要で、[公開得点 CSV](https://img.atcoder.jp/ahc_standings/ahc041/result.csv)
と [入力対応表](https://img.atcoder.jp/ahc_standings/ahc041/input.csv)
は HTTP 403。コンテストの 150 入力とも照合できず、
本番 1 位の得点と比較できないため **未判定** です。
公式ツールの同梱シードは 100 件で、本番 150 件とは確認できません。
この検証は同梱シードとも重複しない、自前の新規シードだけを使い、
外部の解説、サンプル解答、他の提出は開いていません。

## 再現とライブラリ

公式 zip の SHA-256:
`8ff26edd91a700f08a4798a997a559b60f37d1a32217bfbaf63b8122bcec1386`。
`cargo build --release --locked --bin gen --bin vis` で用意します。

```bash
bash problems/ahc041/run.sh build/ahc041 "$gen" "$vis" 7
```

既存の木ライブラリは探索ランナーや静的な木の処理が中心で、
深さ制限のある部分木移動には使えなかったため、
[`BoundedDepthForest`](../../library/bounded-depth-forest.hpp) に切り出しました。
[使用例](../../examples/bounded_depth_forest_usage.cpp) /
[39,600 回の愚直な根経路計算との比較](../../tests/bounded_depth_forest_test.cpp)。
次は、深さの上限で価値の高い部分木を深くできない時に、上限を超える
子孫だけを隣の枝へ動かしてから根元を付け替える複合近傍を試します。

## 深さ上限をまたぐ部分木の複合付け替え（未採用）

前と同じ 13 初期案の最良と、140 ms の内部制限を使います。
通常の単一付け替えができない時の一部で、移動後に深さ上限を超える
子孫の部分木を最大 4 個だけ選び、元の部分木の外にある接続先に
先に移します。適切な隣接頂点がなければ独立した根にします。
元の部分木を移した後で、全操作の正味の差分を一度だけ判定。
不採用なら逆順に付け替え、親・深さ・得点を全て復元します。
ライブラリには、全頂点から親を引き直さずに直接の子を辿る API を
追加しました。

| 新規独立シード | 単一付け替え | 複合も許可 | 複合の勝ち |
|---|---:|---:|---:|
| 開発 12 件 | 5,946,093 | 5,946,737 | 5/12 |
| 凍結後・未調整 24 件 | 11,911,222 | 11,915,249 | 13/24 |

未調整の差は 0.034% で、同じ時間で頑健に改善したとは判断せず、
単一付け替え版を既定のままにします。複合版は
`-DAHC041_COMPOUND_REPAIR` で切り替えられます。
全 72 実行で合法、公式採点・独立再生・C++ の得点が一致。
最大壁時間は 0.190 秒未満（CPU 7 固定）、C++23 単一ファイルも
483,937 点で合法でした。

単独では不可能な付け替えが +18 点になる手計算例と、ランダム操作で
根までの経路を全て引き直す差分検査を追加しました。
本番ケースは使用していません。次に試すなら、複合操作を増やすより、
重い部分木が上限超過を起こす少数の場所だけを先に選び、
切り離しの損失見積りで候補を絞ります。

```bash
bash problems/ahc041/run_compound.sh build/ahc041-compound "$gen" "$vis" 7
```
