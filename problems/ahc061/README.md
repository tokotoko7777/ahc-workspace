# AHC061

[公式問題](https://atcoder.jp/contests/ahc061/tasks/ahc061_a) /
[公式 Rust テスター・ジェネレータ](https://img.atcoder.jp/ahc061/N52XwIfp.zip)。
10×10 の盤面で、接続している自領土と、その隣接セルに進み、
領土を占領・強化・攻撃するインタラクティブ課題です。

## 同時移動の衝突と、接続している領土

基準は手番ごとに各プレイヤーの合法手を BFS で列挙します。
各 AI の公式の評価式・パラメータ範囲で 48 組の仮説を作り、観測した
移動の尤度で仮説の重みを更新します。各仮説のランダム手と
貪欲手（同点は等分）を混合し、各セルへの移動確率を見積もります。
自分は、得点の増減、強い敵に与える損失、衝突の回避と防衛の
近似期待値が最大の手を選びます。現在の盤面と観測済みの行動だけを使います。

追加候補は同じ推定と一手評価を使い、占領後に移動先として
新たに使える中立地・易攻撃地・強化候補の価値、逆に相手が失う
接続先を近似加点します。相手は同時には動かないと仮定して
接続効果を測るため、実際の合同遷移を再現する二手読みではありません。

| 独立シード | 基準の絶対点 | 接続評価あり | 勝・負・同 |
|---|---:|---:|---:|
| 開発 14 件 | 1,426,669 | 1,452,720 | 8・6・0 |
| 凍結後・未調整 28 件 | 2,596,131 | 2,511,876 | 14・14・0 |

開発では改善しましたが、未調整では 3.25% 低下したため既定は基準のままです。
`-DAHC061_ACCESS` で接続評価版を再現できます。全 84 対戦は合法で、
公式テスター・独立リプレイ・C++ の絶対点が一致しました。
CPU 7 固定で両方式の最大壁時間（テスター込み）0.018 秒未満（採用構成で再計測）。
C++23 単一ファイルの対戦は 119,220 点、全ターンの行動も通常版と一致しました。
汎用部品の追加はありません。今回の接続・衝突解決は問題専用です。
次は、同じ相手行動の乱数サンプルで候補を比べ、攻撃・防衛の合同遷移を
相手の最終最大得点も含めて二手先まで評価します。

## 本番比較

絶対点は `round(10^5 log2(1 + S0 / SA))` で、`SA` は最強の AI の得点。
本番 3,000 ケースの相対点和は、各ケースの `round(10^9 YOUR / MAX)`
を合計します。失格ケースは 0 で MAX から除外されます。
2 秒・1024 MiB。

[公式結果](https://atcoder.jp/contests/ahc061/results/json)と
[公式順位ビューア](https://img.atcoder.jp/ahc_standings/index.html?contest=ahc061)。
[公式得点 CSV](https://img.atcoder.jp/ahc_standings/ahc061/result.csv) の
履歴 1,171 人×3,000 件から上記の丸めで 1 位 cuthbert の
**2,424,667,397,941 点**を確認しました。2、3 位も公式結果と一致しました。
[公式入力対応表](https://img.atcoder.jp/ahc_standings/ahc061/input.csv) の
3,000 種は[公式公開種](https://img.atcoder.jp/ahc061/seeds.txt)と順序まで一致
（SHA-256 `24432b101519407fc0e5c2f92f3b939089115b79fd2e71ab3ee737ebc53e0601`）。
今回は開発・検証とも別の種だけを使い、本番入力は実行していません。
したがってこの提出候補の相対点・1 位比較は **未判定** です。
外部の解法・参加者の提出は使っていません。

## 再現

公式ツール ZIP SHA-256:
`9a77bcb9476f6cc2ca0e7360126360cab6d63b0df96d2a8841c13742ee1df5b9`。
`cargo build --release --locked --bin gen --bin tester` で用意します。

```bash
bash problems/ahc061/run.sh build/ahc061 "$gen" "$tester" 7
python3 -m unittest discover -s tests -q
```

`AHC061_TRACE=1` は stderr に各ターンの実際の全行動を記録する、
独立リプレイ用オプションです。標準出力は常に対戦プロトコルのみです。
