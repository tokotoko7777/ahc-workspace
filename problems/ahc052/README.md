# AHC052

[公式問題](https://atcoder.jp/contests/ahc052/tasks/ahc052_a) /
[公式 Rust ジェネレータ・ビジュアライザ](https://img.atcoder.jp/ahc052/ZN1uhrbm.zip)。
1 台のコントローラで全ロボットを同時に動かして床を磨きます。

## 全ロボット共通キーと、個別キーの比較

両版は、長さ 3 までのボタン列をビーム探索し、新たに磨いたマスの
多さを優先します。進展しないときは、未訪問マスを始点とする BFS で
いずれかのロボットを近い未訪問マスへ導きます。
完成しない場合に備え、ロボット 0 に DFS をさせる完全な案を先に
用意します。1 本の木の辺を往復するだけなので 1,800 操作以下です。

基準は全員に同じ方向を割り当てる 4 種類のキー。
候補は同じ 4 種類を退避用に残し、それとは別にロボットごとの
方向をずらした 4 キーと、個別の向き・停止を混ぜた 2 キーを追加。
各版 4 回、1.65 秒の共通締切で、展開するキーの数に応じて
ビーム幅を下げ、一層あたりの展開数の目標をそろえました。
展開結果の重複数は異なるため、実行時間は同一ではありません。

| 新規独立シード | 共通キーの得点 | 個別キーの得点 | 操作合計（共通 → 個別） | 個別キーの勝ち |
|---|---:|---:|---:|---:|
| 開発 12 件 | 27,445 | 28,931 | 4,955 → 3,469 | 12/12 |
| 凍結後・未調整 24 件 | 54,986 | 57,831 | 9,814 → 6,969 | 24/24 |

未調整では操作を 28.99% 削減。全 72 実行で全域を磨き切り、
公式 `vis`、独立再生、C++ の得点が一致。CPU 7 固定で最大壁時間は
0.044 秒未満でした。既定は両版の完成案を比較して得点が高い方、
`-DAHC052_COMMON_KEYS_ONLY` と `-DAHC052_INDIVIDUAL_KEYS` で
各比較版を再現できます。

## 本番比較

30×30、10 台・10 キー、2 秒・1,024 MiB、最大 1,800 回。
全域を磨くと `2,700−操作数`、残りがあれば訪問済みのマス数。
150 ケースの和が最終点で、1 件の不正や時間超過で提出全体が 0。
後日のシステムテストはありません。
[公式結果](https://atcoder.jp/contests/ahc052/results/json)で 1 位は nikaj。
点数掲載はなく、[順位表](https://atcoder.jp/contests/ahc052/standings/json)
はログインが必要です。[得点 CSV](https://img.atcoder.jp/ahc_standings/ahc052/result.csv)
と [入力対応表](https://img.atcoder.jp/ahc_standings/ahc052/input.csv)
は HTTP 403、公式ツールの同梱シードも 100 件で本番 150 件ではありません。
同梱シードとは別の自前シードの評価であり、本番比較は **未判定**。
外部の解説・他の提出・公式サンプル解答は開いていません。

## 再現

公式 zip SHA-256:
`cfc51f8a0bffa1c9513024a82fa1dfc99cdf44ee1484df471ecea9d295825809`。
`cargo build --release --locked --bin gen --bin vis` で用意します。

```bash
bash problems/ahc052/run.sh build/ahc052 "$gen" "$vis" 7
```

C++23 単一ファイルでも 2,399 点でした。壁での停止や異なるロボット
の移動は別シミュレータで検査します。少数の状態を頻繁に複製する
短いビームなので、被覆の状態と位置をビット集合・固定配列に
置き、一般探索ランナーへは移していません。
次は、同じ数のコントローラ案の中で、通過後に未訪問が残る場所を
手がかりにキーを局所変更する案と、独立に振り直す案を比較します。
