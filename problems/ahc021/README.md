# AHC021

[公式問題](https://atcoder.jp/contests/ahc021/tasks/ahc021_a) /
[公式 Rust ツール](https://img.atcoder.jp/ahc021/d17182d7.zip)。
465 個の球を合法な隣接交換だけで並べ、全ての親が直下の子より
小さくなるまでの交換数を減らします。

## Ａ/Ｂ

基準版は、このリポジトリの
[既存の木ビーム例](../../examples/search/ahc021_tree_beam.cpp) と同じ
実装で、比較用に幅を 64 にしました。小さい球から「親がすべて確定した
未確定マス」に置く方針です。使用した既存ヘッダの出典コメントはそのままにし、
コメント中の外部リンク、第三者の解説・記事・提出コードは開いていません。

別案は、未確定の最小球と最大球の両方を調べ、その時点で動かしやすい側を
選びます。最小球は親が確定したマス、最大球は子が確定したマスへ、
未確定マスだけを通る BFS で運びます。確定順と行き先を同時に選べます。
未確定部分の各連結成分には親なし・子なしのマスが存在するため、
既に確定した球を崩さずに続けられます。複数の優先順と固定乱数種で
試し、交換数が最小の完成手順を選びました。

| 独立生成の共通入力 | 既存ビーム | 両端確定 | 両端確定の勝ち |
|---|---:|---:|---:|
| 開発 10 件 | 905,175（18,965 手） | 886,080（22,784 手） | 0/10 |
| 版の凍結後・未調整 20 件 | 1,813,745（37,251 手） | 1,774,960（45,008 手） | 0/20 |

全 60 実行が完成し、交換の合法性と公式採点は独立再生結果と一致
しました。CPU 7 固定の最大壁時間は既存ビーム 0.510 秒未満、両端確定
0.541 秒未満。双方同程度の時間で比較しましたが、両端確定はどのケース
でも勝てず、`main.cpp` の既定は既存ビームのままとしました。

## 本番比較

操作は 10,000 回まで。違反ペアが 0 なら `100000−5K`、
残っていれば `50000−50E`。150 件の得点を合計して最大化し、
1 件でも非 AC なら提出全体が 0 点です。実行時間 2 秒、
メモリ上限 1,024 MiB。コンテスト後のシステムテストはありません。

本番 1 位は **13,589,420 点**。
[AtCoder 提供の ALE-Bench アーカイブ](https://huggingface.co/datasets/SakanaAI/ALE-Bench/blob/main/ahc021.zip)
を SHA-256 `aea95345b11743f87a02ec87c075e00d0686925de9c51d84f21d6f4d624dcd5a`
で照合し、順位・得点の CSV だけを確認しました。
公式ローカルツール同梱の seed 0〜99 が本番 150 件と同じという根拠はなく、
公式問題文には本番シードの公開記載がありません。AtCoder 再提出や
ALE-Bench の Docker を使うブラインド非公開評価は行っておらず、
非公開入力は参照していません。**厳密な本番順位は未判定**です。

## 再現とライブラリ

公式配布 zip の SHA-256 は
`4b6a4c445137b614c20ef6801fa217b1192259062d175d66ab4a7563a249859e`。
`cargo build --release --locked --bin gen --bin vis` でビルドし、
引数に公式の `gen` と `vis` の絶対パスを指定します。

```bash
bash problems/ahc021/run.sh build/ahc021 "$gen" "$vis" 7
```

両版の C++23 提出用単一ファイルを生成してビルドします。
既存ビームの親側だけを管理する仕組みは、子側からも確定する今回に合わず、
両側の残り次数を管理する
[`TwoSidedDagFrontier`](../../library/two-sided-dag-frontier.hpp) を追加しました。
[使用例](../../examples/two_sided_dag_frontier_usage.cpp)、
[1,000 個のランダム DAG で愚直な判定と比較するテスト](../../tests/two_sided_dag_frontier_test.cpp)、
[API](../../docs/LIBRARY_REFERENCE.md#twosideddagfrontier)。

次は、既存ビームの合法な完成手順を直接短くします。交換列を末尾から
見て、後続操作による位置の写像を記録すると、途中の 1 交換の省略が
最終盤面のどの 2 マスの交換に等しいか分かります。そのマスに関係
する親子条件だけを検査し、完成条件を保つ交換を省略します。
