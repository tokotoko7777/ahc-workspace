# AHC006: 公式配布100ケースでの比較

[公式問題文](https://atcoder.jp/contests/ahc006/tasks/ahc006_a) / [公式ツール・配布100件](https://img.atcoder.jp/ahc006/c21daebb77aa4d38d65f4d7f7c7249.zip)。
公式配布 seed 0–99 の100件の各整数得点を合計。2,220,425点を超えることが目標。
本番と別入力なので、本番1位超えの判定ではない。

通常設定の既存版（公開ソース `0e7380c86bf2f895cc47b0f44cd976f7bb01e9cd`）は **2,078,408点**、
目標を厳密に超えるにはあと142,018点。[ケース別結果](baseline-results.csv)、[測定時の単一ファイル](baseline.single.cpp)。
全100件合法・公式と独立採点一致。最長実測1.857923秒、中央値1.853609秒。
総走行距離381,574、ケース中央値3,815。
ソース SHA-256 `7ad27e14ea732bc4eb644e0a27acd75b2f4431fe2217447a8da21d76ae50ab28`、
CSV SHA-256 `92382ca3416a27203cbad7ba9b969ae5870881cac7edb8c93b8c2bab88a247a6`。

## 再現手順

公式ZIPを展開したディレクトリで `cargo build --release --locked`。リポジトリのルートで
`TOOLS` に公式ツールのディレクトリを設定して実行する。GNU C++23、追加最適化フラグは不要。出力は直列に検証する。

```sh
E=problems/ahc006/experiments/official100
g++ -std=c++23 "$E/baseline.single.cpp" -o solver
python3 "$E/run100.py" . "$TOOLS/in" "$TOOLS/target/release/vis" out --entry "baseline=$PWD/solver"
```

時計で探索を終えるため、マシンや負荷の違いで探索回数・得点は変わり得る。

## 注文入替の挿入位置の高速化

対称距離表で新規集荷・配達点への距離を行単位で参照し、前の位置で読んだ距離を再利用。
合成2,048候補で距離差分と2つの挿入位置が従来版と一致。
固定作業を交互6回計測し、挿入走査だけで約4.7倍。近傍の定義や同点規則は変更していない。

公式配布100件では [**2,128,693点**](pair-scan-results.csv)（+50,285、74勝0分26敗）、
総距離370,198、全件合法・両採点一致、最長1.881348秒。
[単一ファイル](pair-scan.single.cpp)は GNU C++23 以外の追加最適化フラグなし。
ソース SHA-256 `7963739a08141a1407c776d781a04d0023e7a2e921fd815c5eba96c35d8653a2`。

## 経路と注文の近傍を比較

| 方式 | 公式配布100件 | 基準との差 | 最大秒 |
|---|---:|---:|---:|
| [隣り合う2区間の入替](block-sa-results.csv) | 2,071,126 | −7,282 | 1.858461 |
| [集荷と配達の領域を分けて初期注文を選ぶ](directed-cohort-results.csv) | 2,061,829 | −16,579 | 1.871217 |
| [未選択注文を最大4件、最良挿入費用で比較](pair-tournament-results.csv) | **2,177,675** | +99,267 | 1.858030 |

いずれも全件合法・両採点一致。候補4件版は高速挿入走査だけの版から+48,982点（72勝28敗）、
目標を厳密に超えるにはあと42,751点。[単一ファイル](pair-tournament.single.cpp)、
SHA-256 `1e1b10bfea6141eab0ffbfaad2232c95fc6a6f24790fd47d33d5fa1298d49662`。
固定テストで95,640の合法手（うち6,029交換）を全距離と照合した。
公式100件で試行回数は高速走査単体の863,304,832から482,623,680に減ったが、
1回の交換で評価する候補を増やした分、得点は伸びた。

## 計測用対照と距離表の前計算

- [ログのみを追加した基準の再計測](baseline-stats-results.csv)は2,092,177点。通常基準との差+13,769点は、時計ベースのばらつきを含む。100件の探索反復389,475,136に対し、注文差し替えの行再利用版では863,304,832（約2.22倍）だった。旧新版の固定作業テストはこれと別。
- [途中で複数注文を同時に換える版](live-lns-results.csv)は2,050,844点（基準−27,564）、最長1.858174秒。合成の改善が公式100件では再現しなかった。高速版に移したものと、起動回数を抑えた合成テストも採用しなかった。
- [座標成分の連続配列から同じ距離表を作る版](packed-table-results.csv)は2,135,965点（直接の行再利用版+7,272）、最長1.854615秒。固定作業では提案経路を変えず、公式100件の探索反復は962,018,752（直接版+11.43%）。[測定した単一ファイル](packed-table.single.cpp)。

全版100件合法・公式と独立の採点一致。

## 集荷・配達の両方が近い注文から交換候補を出す

未使用注文4件の候補を、従来どおり無作為2件と、集荷・配達の両端が似た注文2件に分ける。
対象は外す予定の注文と、まだ選ばれている別注文。すべて従来と同じ正確な最良挿入距離で比較し、
出力は必ず50件・集荷先行・発着地点固定。

公式配布100件は [**2,234,199点**](geometric-selection-results.csv)。
目標の2,220,425点を **13,774点** 上回った。直接の親から +56,524、77勝23敗。
全件合法・両採点一致・最長1.856221秒、総距離347,930。これは本番順位の比較ではない。
[測定した単一ファイル](geometric-selection.single.cpp) SHA-256
`35004ac843346939e3394f3d0fb70777f3a7d53a11766d1c032593f5c87f8448`。

## 同じ経路への挿入候補を広げた追試

注文を外した直後の経路を1回だけ構成し、その辺の距離を候補間で共有。元の4候補と同じ
乱数・挿入位置・採否・最終距離になることを合成4件×3反復の固定作業で確認。
時計で区切る公式100件では [4候補版2,168,677点](batch-k4-results.csv)、
[8候補版2,202,697点](batch-k8-results.csv)。8候補版は4候補版より+34,020点、
探索反復は498,795,712→336,278,656。候補を倍にするだけでは、幾何候補を入れた4候補版の
2,234,199点には届かなかった。いずれも100件合法・両採点一致。

## 幾何候補版に前計算の高速化を合成

座標成分ごとの距離表生成だけ変更。合成で全約2,803万距離と固定提案280,000枠が一致し、
前計算中央値85.108→10.390 ms。ただし公式100件の試行4.6787億→4.8419億（+3.49%）で
[2,229,101点](geometry-packed-results.csv)となり、直接の親より−5,098点。
全件合法・両採点一致、最大1.859077秒。[単一ファイル](geometry-packed.single.cpp)。
得点最高の幾何候補版は置き換えず、先に分離した未使用100件で確認する。

## 調整に使っていない100件での対比較

公式ジェネレータの未使用 seed 22,000,000〜22,000,099。幾何候補を採用した版と、無作為4候補の前版を、
同じ1件で実行順を交互に入れ替え直列で測った。
- 幾何候補版 **2,220,221点**（総距離350,682、最大1.853920秒）。
- 無作為4候補版 **2,180,464点**（総距離358,988、最大1.867182秒）。
- 差 **+39,757点**、66勝34敗。全200出力で合法・公式と独立採点一致。
- 別集合では2,220,425点に204点届かず、公式配布100件での目標判定・本番順位とは分ける。
  [ケース別結果](geometric-holdout-results.csv)。

公式ツールの `gen` を使い、別ディレクトリで `seq 22000000 22000099 > seeds.txt`、
`gen seeds.txt` を実行。配布入力を上書きしない。上の `run100.py` に別ディレクトリの `in/` と
`--entry selection=幾何候補版の実行ファイル --entry tournament=前版の実行ファイル` を渡せば同じ比較になる。
