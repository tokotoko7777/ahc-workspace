# AHC017

[公式問題と採点規則](https://atcoder.jp/contests/ahc017/tasks/ahc017_a) /
[公式 Rust ジェネレータとビジュアライザ](https://img.atcoder.jp/ahc017/a7a9e57e.zip)。
工事のないときに比べて最短距離が増えにくいよう、各道路の工事日を割り当てます。

## Ａ/Ｂ

基準版は、次数の小さい頂点に接する辺から日へ配置します。初期配置と
変更時に、同日に新しく閉じる辺の端点が引き続きつながっているかを BFS
で検査して、連結だった日を切断しないようにします。各日 K 本以下。
初期の連結構築に失敗しても、合法な上限だけは保証する割当を返します。
基準版では同じ端点を持つ工事が同じ日に重なることだけを代理評価として
罰し、1 辺の日変更と 2 辺の日交換を焼きなましします。

迂回路版はこれに、ある工事辺とその最短迂回路上の辺を同じ日に
閉じる罰則を足します。重みは元の道路網から 20 個の出発頂点を抽出した
最短路木の通過数と、迂回路の増加距離で近似します。端点だけでなく、
少し離れた道路同士の干渉も避けます。同じ初期割当と 60,000 個の
提案上限を使い、実行時間の打ち切りも設けています。

| 生成シードの同じ入力 | 基準版の絶対不満度合計 | 迂回路版 | 減少 | 迂回路版勝ち |
|---|---:|---:|---:|---:|
| 新規開発 8 件 | 275,510,228 | 229,174,477 | 46,335,751 | 7/8 |
| 版の凍結後・未調整 14 件 | 195,636,386 | 189,307,900 | 6,328,486 | 10/14 |

全 44 実行で容量を守り、全ての工事日にグラフが連結でした。
独立した全頂点対最短路検査と公式 `vis` が丸め後まで一致しました。
CPU 7 固定の最大壁時間は基準版 0.033 秒未満、迂回路版 0.045 秒未満
（採点時間は別）。提出用単一ファイルでも未調整 1 件で 7,664,306 と
一致しました。作業ブランチの既定は迂回路版です。凍結した迂回路版
SHA-256: `7a63371ff4db9cacb6f87b3f13d4ac9052e63c66916d1d0a8179b48ad6b7f414`。

## 本番順位との比較

全ての日・異なる頂点対について、平常時からの最短距離増分を平均し、
1,000 倍を四捨五入した値が絶対不満度です。到達不能な距離は `10^9`。
上の比較は絶対不満度の合計で、小さい方がよいです。本番は 2,000 件の
`round(10^9 × そのケースの全参加者の最小不満度 / 自分の不満度)`
の合計を最大化し、非 AC はそのケースだけ 0 点で、基準値の集計からも
除外されます。最終順位に反映される最終の提出だけが対象です。
各ケースの制限は 6 秒・1,024 MiB です。

本番 1 位の相対点は **1,993,227,663,417 点**。
[AtCoder 提供の ALE-Bench アーカイブ](https://huggingface.co/datasets/SakanaAI/ALE-Bench/blob/main/ahc017.zip)
を SHA-256 `d0df8fa1417278e9651668acc68d3e015497d1da6b5f2ebe599be27be07efa5d`
で照合し、順位・得点 CSV だけを確認しました。
[本番シード 2,000 件](https://img.atcoder.jp/ahc017/seeds.txt) の
SHA-256 `0522b6c3da4e413908209488368988ebce3b3809c0d9278dc9adaf804896fa23`
は問題文と一致しました。開発・確認の入力はこれと重複しません。
本番のケースは生成・評価していません。仮に同じ入力で絶対不満度を
計算しても、各ケースの本番最小不満度なしには本番 1 位の相対点と同じ
物差しになりません。基準値は未取得、本番比較は未判定です。

## 再現・ライブラリ

公式配布 zip SHA-256:
`a143383aef48481af19fe83d8bb2397feb641ca17bc6d5cb685ce085938c8ab7`。
`cargo build --release --locked --bin gen --bin vis` で公式ツールを用意し、
両方の絶対パスを指定します。

```bash
bash problems/ahc017/run.sh build/ahc017 "$gen" "$vis" 7
```

提出用 C++23 の 1 ファイルを生成してビルドします。
端点の衝突と迂回路の衝突は、同じラベルの要素間の疎な罰則として
一緒に管理できます。2 辺を交換した時に両者間の項を二重計上しない
よう、汎用の [`SparseGroupConflicts`](../../library/sparse-group-conflicts.hpp)
へ切り出しました。[使用例](../../examples/sparse_group_conflicts_usage.cpp)、
[800 個のランダムな罰則グラフで全再計算と突き合わせるテスト](../../tests/sparse_group_conflicts_test.cpp)、
[API](../../docs/LIBRARY_REFERENCE.md#sparsegroupconflicts)。
既存の Dijkstra は辺 ID を返さず、辺 1 本を除く経路を頻繁に求める
用途に合わなかったため、経路木と除外辺の処理は問題側に実装しました。
既存提出や解説は使用していません。

次は、迂回路が一本塞がれたかどうかでは表れない複数経路の代替性を
扱うため、候補とする 2 日について少数の出発頂点からの距離増分を
直接再評価します。同日交換で影響した短い経路木だけを更新できるかと、
別の未調整入力で伸びるかを検証します。
