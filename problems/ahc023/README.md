# AHC023

[公式問題と採点規則](https://atcoder.jp/contests/ahc023/tasks/asprocon10_a) /
[公式 Rust 生成器とビジュアライザ](https://img.atcoder.jp/ahc023/asprocon10_5XtyY7PgVPtBANvV.zip)。
水路と栽培中の区画を避けて植付・収穫する計画を作ります。

## Ａ/Ｂ

入口から幅優先で深さを付けます。各深さで一つ手前の深さから親を
選ぶ際に、未割当の子を多く担当できる親を優先し、できるだけ多くの
区画を葉にします。基準版は葉だけを使い、各区画で未使用の作物を
閉区間の重み付きスケジューリングで選びます。植付日は指定の最終日
`S`、収穫は `D`。木の内部はすべて通路です。

動的通路版は、同じ葉の計画を維持した上で、深い内部区画から順に
作物を追加します。ある区画の全ての子孫について、植付日・収穫日を
集め、その日を一日でも含む作物はその区画に置きません。したがって
子孫の作業時には入口からの木の道が常に通れます。入口は空けておき、
同日の作業順に依存しないよう前後の端点も含めて通行を保証します。

| 独立生成の共通入力（水路パラメータ d を均等化） | 葉のみ | 動的通路 | 増加 | 動的通路勝ち |
|---|---:|---:|---:|---:|
| 開発 12 件 | 5,447,400 | 6,551,125 | +1,103,725 | 12/12 |
| 凍結後・未調整 24 件 | 10,825,325 | 13,194,825 | +2,369,500 | 24/24 |

未調整で +21.9%。全 72 実行で毎日の植付・収穫を独立再生し、公式
`vis` と得点が一致しました。Linux CPU 7 固定の動的通路版の
最大壁時間は 0.009 秒未満。初回の作業ブランチ既定は動的通路版です。
凍結したバイナリ SHA-256 は
`87a1ca2ae0f370e104b83d2f4b69590cb0eed6d79c5b625797adc0bbc51c5a69`。

## 本番条件

採用した作物ごとに `D−S+1` を足し、`10^6/(HWT)` を掛けた絶対点を
最大化します。対象のケースでは整数です。2 秒・1,024 MiB。
本番 2,000 件（生成時の水路パラメータ d=1〜4 が各 500 件）の和を
比較し、非 AC はそのケースだけ 0 点です。

[公式本番シード](https://img.atcoder.jp/ahc023/seeds.txt) は 2,000 件、
公式問題文の SHA-256
`0c2ffe8037c0c232ed9775b89a892fc1f68709a1582c83fd6bb609244cefcf32`
と一致しました。開発・確認の各シードはこれと重複しません。
[AtCoder 公開の最終順位ビューア](https://img.atcoder.jp/ahc_standings/index.html?contest=ahc023)の
[採点 CSV](https://img.atcoder.jp/ahc_standings/ahc023/result.csv)
（SHA-256 `34fbe2ecf682d2d6bc6472dff1e636911bca02cd937f627db678ca1cf53acd00`）
で、各参加者の raw 得点を非 AC は 0 として 2,000 件集計した
本番 1 位は **1,782,120,500 点**（sugim48）です。
上位 3 人の順序は [公式結果](https://atcoder.jp/contests/ahc023/results/json) と一致します。
同じ 2,000 ケースで凍結した閉区間の動的通路版を再現採点した結果は
**1,100,483,250 点**、差は **681,637,250 点**で未達です。
全件合法で公式 `vis` と独立再生が一致し、最大壁時間は 0.036 秒未満
（CPU 7 固定）でした。これは AtCoder への提出結果ではありません。
後述の植付・収穫分離版と兄弟葉フロー版は本番条件で未計測です。

## 再現とライブラリ

公式 zip の SHA-256:
`0934a5019b97236d97907347f3910feb4fe4bd7c77bf016c76b9f251da08f7e7`。
`cargo build --release --locked --bin gen --bin vis` で公式ツールをビルドし、
`gen` と `vis` の絶対パスを指定します。

```bash
bash problems/ahc023/run.sh build/ahc023 "$gen" "$vis" 7
```

C++23 の提出用単一ファイルも生成し、未調整集合の 1 件で通常版と
同じ 549,125 点を確認しました。既存の `schedule.hpp` は探索の
温度等を変える補間用で、閉区間を選ぶ DP はありませんでした。
そこで使用不可日と既使用の作物を除ける
[`CalendarIntervalPacking`](../../library/calendar-interval-packing.hpp) を
追加しました。[短い例](../../examples/calendar_interval_packing_usage.cpp)、
[1,000 件の部分集合全列挙テスト](../../tests/calendar_interval_packing_test.cpp)、
[API](../../docs/LIBRARY_REFERENCE.md#calendarintervalpacking)。

実装の方針は、公式問題の正しい URL を探す前に立てました。URL を
探した検索結果に解説ページの抜粋が混ざりましたが、解説リンクを
開いたり掲載内容を実装に使用したりしていません。公式の解答例や
他の提出コードも参照していません。

次は、子孫の植付と通路区画の植付が同日なら子孫を先に、収穫同士なら
通路区画を先にすることで、閉じる日を朝と夕方に分けて内部を使います。
同日の逆相の作業は引き続き禁止し、独立再生で確認します。

## 植付・収穫の同時刻を区別する追加実験（採用）

内部区画の作物が `[S,D]` に植わる場合、子孫の植付は `(S,D]`、
子孫の収穫は `[S,D)` だけを禁止します。S の月に同じ植付があるなら
子孫を先に、D の月に同じ収穫があるなら内部区画を先に処理できます。
一方、D の月の植付はまだ収穫前なので不可、S の月の収穫は植付済み
なので不可です。植付と収穫を別の子孫カレンダーとして累積して、
候補区間がどちらの制約にも合うようにしました。

| 本番と重複しない新しい共通入力 | 初回の閉区間版 | 植付・収穫分離版 | 増加 | 分離版勝ち |
|---|---:|---:|---:|---:|
| 開発 16 件 | 8,777,400 | 10,001,200 | +1,223,800 | 16/16 |
| 凍結後・未調整 28 件 | 15,388,700 | 17,383,850 | +1,995,150 | 28/28 |

未調整で +13.0%。全 88 実行で合法・公式採点・独立再生が一致しました。
最大壁時間は 0.014 秒未満（分離版、CPU 7 固定）。同じ月の同じ種類の
作業だけが順序変更で通れることと、逆種類の二例が無効なことを
`phase_test.py` で確認しています。分離版を作業ブランチの既定とし、
初回版は `-DAHC023_CLOSED_WINDOWS` で選べます。
本番ケースで分離版の評価はしておらず、設計にも本番結果は使っていません。

```bash
bash problems/ahc023/run_phase.sh build/ahc023-phase "$gen" "$vis" 7
```

次は、葉の作物を別々に選ぶのではなく、隣接する子孫の植付・収穫を
同じ日にそろえて、幹側の使える連続日を長くします。単に植付日の種類を
減らすだけでは収穫が増えないので、木の部分ごとの二つの作業日の種類数と、
葉の基礎得点を同時に見ます。

## 兄弟葉をまとめて再配置する追加実験（不採用）

植付・収穫分離版の解を作った後、同じ親を持つ葉が 2 個以上ある
すべての集合を対象に、祖先と集合外を固定して 1 回ずつ解き直します。
親から入口までの経路が同じなので、葉間で植付・収穫の可否が共通です。
祖先の作物が `[P,D]` にあれば葉の植付 `(P,D]` と収穫 `[P,D)` を
禁止します。各候補の植付を `S` 以前の最後の合法月に固定しても、
それ以前に植えるより占有が短いため、同じ固定祖先の下で不利になりません。
同一区画では植付が収穫より先なので、区間は両端を含みます。

集合の既存作物と未使用作物を候補とし、月 `s→D+1` に容量 1、
費用 `S−s` の辺、毎月の空き区画には費用 1 の辺を張ります。
区画数だけ流し、得点が厳密に増えた時だけ置き換えます。
祖先を共通にしない葉へ広げると空き月が同じとは限らず、このモデルの
対象外です。例えば片方の祖先だけがその月に収穫する場合、同日の植付は
もう片方にしか置けません。共通マスクを持つ兄弟葉も、祖先ごと
組み直す近傍ではありません。

| 新規独立シード | 分離版 | 分離版 + 兄弟葉フロー | フロー勝ち |
|---|---:|---:|---:|
| 開発 12 件 | 7,462,425 | 7,462,425 | 0/12 |
| 凍結後・未調整 24 件 | 14,779,075 | 14,779,075 | 0/24 |

全 36 ケースで点数は同じでした。フローを使う版は同じ実装に追加の
最適化を加えたため、等時間比較ではありません。確認集合の中央値は
8.68 → 11.82 ms、フロー全体の最大は 0.044 秒未満（CPU 7 固定）。
全 72 実行で公式 `vis` と独立再生の点数が一致し、提出用 1 ファイルは
同じ入力で実験実行ファイルと出力が一致しました。
本番入力・スコアはこの実験や調整に使っていません。既定は分離版のままです。

```bash
bash problems/ahc023/run_flow.sh build/ahc023-flow "$gen" "$vis" 7
```

既存 [`MinCostFlow`](../../library/min-cost-flow.hpp) は非負費用のため、
重みを単純に負費用にせず、空き枠 1 か月を費用 1 として変換しました。
区間の変換と枠復元を
[`pack_parallel_intervals`](../../library/parallel-interval-packing.hpp)
に分けています。[使用例](../../examples/parallel_interval_packing_usage.cpp) と
[小問題 1,200 件の全列挙比較](../../tests/parallel_interval_packing_test.cpp)
があり、逐次一枠ずつの最適化では取りきれない固定例も含みます。
次は同じ集合の葉の入替だけではなく、祖先作物を 1 個解放し、空いた月で
増えた子孫の得点と祖先の失点を同時に比較するのが有望です。
