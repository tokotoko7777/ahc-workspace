# AHC001: 単一ブロッカーを縮める試行（不採用）

既存の min-cut 版（基点 `0c5fd37969ac55cbcb0ad2c05972a9dec3d8ef39`）は、直交方向に
重なる長方形の順序を保持します。そこで不足している長方形の隣のブロッカーを
直交方向に縮め、一つの分離制約を外す試行を検証しました。両軸の min-cut と
ブロッカーの再拡張を適用し、全体で改善しない試行は元の配置へ戻します。

両群は同じ v64 出力を事前に純粋な min-cut で磨いた配置から始めます。
各候補で同じスナップショットに戻し、ブロッカーを一時的に縮める操作の有無
だけを変えて、同じ順の両軸 min-cut と再拡張を適用しました。1ケース最大12ペア、
処理開始から0.11秒を超えた後は次のペアに着手しません。開始済みペアの終了と
入出力も実測時間に含めるため、これは提出用の時間制限ではありません。

| 指標 | 結果 |
|---|---:|
| 本番・既存の開発/未調整と重ならない新規開発ケース | 8 |
| 仕上げなしの既存配置 / 比較中の3種類の出力 | 計32、公式採点と独立検査一致 |
| 共有の開始配置から純粋 min-cut / 一時縮小ありの平均改善 | +7,276.5 / +7,787.75 |
| 純粋 min-cut に対する一時縮小ありの平均差 / 中央値差 | +511.25 / +0.5 |
| 一時縮小ありの勝敗 | 4勝4分 |
| ペア試行計 / 狙った分離方向が変わった一時縮小あり試行 | 83 / 4 |
| 最も長い比較プロセス実測 | 0.144745秒 |

採用した8配置のいずれにも、ある一組の長方形が「x軸のみで分離」から
「y軸のみで分離」（または逆）へ変わった例はありません。計測コストに
見合う改善もなく、**通常の解答には統合しません**。次に試すなら、障害を
除くだけでなく、狙った交差の成立を暫定制約として強制し、途中の失点を
許してから全体を採否判定します。本番ケース別の結果は参照・調整していません。

## 再現

リポジトリのルートで実行します。`TOOLS_DIR` は問題文の公式配布物にある
Rust の gen/vis を `cargo build --release --locked` したディレクトリです。
Linux で空いているCPUを指定する場合は各 Python コマンドの前に
`taskset -c CPU番号` を付けられます。測定は並列化しません。

```sh
E=problems/ahc001/experiments/topology_v1
W=$(mktemp -d)
T=$(cd "${TOOLS_DIR:?gen/visをビルドしたtoolsディレクトリ}" && pwd)
mkdir -p "$W/input"
python3 "$E/seeds.py" > "$W/dev-seeds.txt"
(cd "$W/input" && "$T/target/release/gen" < "$W/dev-seeds.txt")
g++ -std=c++23 -O3 problems/ahc001/main.cpp -o "$W/v64"
g++ -std=c++23 -O3 "$E/topology.cpp" -o "$W/topology"
python3 problems/ahc001/benchmark.py "$W/input/in" "$W/baseline" --time 4.8 --entry "v64=$W/v64" --vis "$T/target/release/vis"
python3 "$E/run.py" "$W" "$W/topology" "$T/target/release/vis"
```

`RESULTS.csv` と `SUMMARY.json` は作業先へ出ます。時間で停止する焼きなましの
ため、環境や負荷が異なれば再計測スコアは変動します。
