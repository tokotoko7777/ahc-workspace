# AHC001: 強制的な軸順序変更を v64 の局所探索に組み込む

[本体の説明](../../README.md) · [前回の単一ブロッカー診断](../topology_v1/README.md)

前回は、一方の長方形を縮めて制約を一時解除しても、採用した最終配置では
x 軸だけで分離していた組が y 軸だけで分離する（または逆の）例が
ありませんでした。今回は同じ操作の再試行ではなく、分離を直交軸へ
切り替えた中間配置を明示的に構成して固定します。

1. v64 の後半の地域再構築で、元配置が片方の軸だけで分離している
   近傍ペアを最大3組見る。
2. 通常どおり局所の長方形を指定点に縮める。そのうえで対象ペアは
   新しい分離軸上の別々の半平面に置き、元の軸上で両方が同じ整数の
   座標を含むようにする。これにより「短くするだけ」ではなく、
   旧軸で重なり新軸で分離することを強制する。
3. 外側の固定長方形、局所の指定点、境界全てを確認した候補だけ
   暫定採用。目標面積を保つ候補を探し、ペア全体で最大0.06の一時失点を
   許す。成功時は2枚とも固定して他の長方形を通常の局所探索で再拡張。
   失敗時は元の地域再構築へ戻る。地域全体が改善しなければ全体を
   元に戻す。
4. 実行時間は両群同じ 4.8 秒、同じ乱数 seed 0、variant 64。
   ねじり候補の検査は1箇所につき5 ms、新規検査は4.785秒以下。
   大域の反復数は消費時間の違いで変動する。受理した軸変更回数と
   その地域改善は別に記録し、最終スコア差と混同しない。

公開本番1,000ケースのケース別得点・出力は参照しない。v64 の
凍結済み比較は **993,411,282,631**、本番1位 **993,823,071,683**。
新しい開発8件と未調整8件のシードは別の SHA-256 接頭辞で固定し、
公開本番の seed 値と既知実験 seed に重ならないことを確かめる。
各ケースの配列・境界・指定点・面積を検査し、公式 Rust 採点器と
一致することを確認する。計測を直列で交互に実行する。

## 再現

公式 tools ディレクトリで `cargo build --release --locked`。
公式の公開 `seeds.zip` から抽出した `seeds.txt` は新規シードとの
重複検査にだけ使う。

```sh
P=problems/ahc001
E=$P/experiments/forced_precedence_v2
D=$(mktemp -d)
# 元の v64 を独立した作業木で凍結コミット815b743から組み立てる。
git show 815b743:problems/ahc001/main.cpp > "$D/v64.cpp"
# マクロなしでは相対依存ヘッダを必要としない。
g++ -std=c++23 -O3 -DAHC_DEFAULT_SECONDS=4.8 "$D/v64.cpp" -o "$D/v64"
python scripts/bundle.py "$P/main.cpp" -o "$D/submission.cpp"
g++ -std=c++23 -O3 -DAHC_FORCED_TWIST -DAHC_DEFAULT_SECONDS=4.8 "$D/submission.cpp" -o "$D/twist"
python "$E/benchmark.py" "$GEN" "$VIS" "$D/v64" "$D/twist" "$OFFICIAL_SEEDS" "$D/paired"
g++ -std=c++23 -O3 tests/ahc001_forced_precedence_test.cpp -o "$D/test"
"$D/test"
```

実測では元の公式評価で固定したバイナリをそのまま使用。
固定時間の探索のため再計測スコアは実行環境で変化する。

## 結果

| 条件 | v64平均 ↑ | 軸変更版平均 ↑ | 軸変更版 勝/分/負 |
|---|---:|---:|---:|
| 新規開発 8件 | 993,135,988.00 | 993,803,224.88 | 7/0/1 |
| 未調整確認 8件 | 993,694,709.25 | 993,234,958.75 | 2/0/6 |

未調整側の平均差は **−459,750.50**、中央値差 **−793,374**。
全32出力が合法で公式採点と一致。最大実測4.821568秒。
423組を検査して154組で、実際に旧軸で重なり新軸だけで分離する
合法な暫定配置を構築したものの、地域全体を改善して採用できた回数は
**0**。元のv64でも今回の試行では地域再構築が一度も受理されなかった。
開発側に見えた最終得点の差を強制ねじりの直接効果とはみなさない。
**既定案に採用せず、公式本番の再監査もしない。**
[測定記録](results.csv) と鏡映した両軸の構成テストを保存した。

使用した v64 バイナリ SHA-256:
`c9689986319fe53ac94c0d5567d708274b1aff13bf8cea22e16e424ca354ed7a`。
軸変更版バイナリ SHA-256:
`bf6eb9b93f3d7812d1cad018ccbfe1269748d69e334090f47e32cd0417fb03b8`。
4.8秒の時間条件により別環境での得点完全再現は保証しない。
