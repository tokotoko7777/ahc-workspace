## 代表点削除の差分化

削除時に以前の2経路と新しい1経路だけを差し引き、変化した区間に接する道路だけを再確認する。最短経路に同コストの候補が複数あると、逆向きは異なる経路を取り得るため、有向の訪問区間を個別に保持。合成10マップの2,219削除候補で全経路を展開した照合と一致。固定作業では採用順序と移動文字列が一致し、削除処理は4〜9倍。

公式配布100件では [22,911,304点](speed-cover-results.csv)、基準比−11,953点（31勝41分28敗）、全件合法・完全可視・両採点一致。最大2.620920秒（基準2.709380秒）、中央値2.609492秒（基準2.638273秒）、SA総試行数477,892,608（基準445,565,440）。時計で探索を切るため公式点の小差や試行数を差分処理だけに帰属しない。得点最良の基準版は維持する。[単一ファイル](speed-cover.single.cpp)は `g++ -std=c++23` のみでビルドした。

## 橋を通る回数の診断

基準版の経路を変更せず、道路グラフの橋を調べた。橋を起点から遠い側に渡った先に、橋と同じ直線区間だけでは見えないマスがあると、その橋を通る必要がある。100件で必須と判定した1,458本はすべて往復一度だけ。任意の28,205本は一度も渡っておらず、橋の通過を減らせる移動コストは0だった。成分の内部経路には別途改善の余地がある。

```sh
python3 problems/ahc005/experiments/official100/bridge-audit.py BENCHMARK_ASSETS
```

`BENCHMARK_ASSETS` には公式入力 `in/` と測定済みの `baseline100/baseline/` を置く。探索・採点の再実行は不要。

## 最短路前計算のバケット化

正の小さな進入費用に対して、優先度付きキューを10個の循環バケットに置換。同距離の前駆は旧版と同じIDを選び、旧版と全端点距離・前駆・初期経路が合成60マップで完全一致。固定作業ではN=25〜65の前計算が4.7〜5.6倍。ただし探索を含む全体がその倍率になるわけではない。

公式100件では [22,878,088点](bucket-paths-results.csv)、基準比−45,169点（27勝41分32敗）。完全可視・合法・両採点一致100件、最大2.705513秒。SA総試行は487,816,192（+9.48%）、ケース中央値4,844,800（基準4,448,000）。試行数は増えたが最終得点は伸びず、今回の最高得点版には採用しない。[単一ファイル](bucket-paths.single.cpp)は `g++ -std=c++23` のみでビルドした。
