# AHC031

[公式問題](https://atcoder.jp/contests/ahc031/tasks/ahc031_a) /
[公式 Rust ジェネレータ・ビジュアライザ](https://img.atcoder.jp/ahc031/PJcas1sL.zip)。
予約を互いに重ならない長方形に割り当てます。

## 一列から、日をまたいで列を固定する構造へ

基準版は会場の全幅を使う一列に予約の昇順で配置します。
需要に必要な高さを切り上げ、収まらなければ削った時の面積不足が
最も小さい高さから詰め、余った高さは末尾の区画に寄せます。
各予約の全日最大面積が一列内に収まる場合は全日共通の高さを使います。

候補版では会場を複数の縦列に分け、列境界と各列の予約グループを
全日共通にします。固定の縦壁に変更費用は発生せず、同じ列内の
横壁の座標差だけを数えられます。列幅の移動と予約グループの
境界移動を試し、基準版も候補として残して最良の案を出力します。
列数 2〜10、4 初期化、48 反復ずつの固定回数。基準版に追加で
構造探索を行う比較であり、等時間の比較ではありません。

| 公式生成器で生成した新規シード | 一列（絶対点合計） | 固定列構造 | 固定列の勝ち |
|---|---:|---:|---:|
| 開発 16 件 | 16,864,516 | 11,661,690 | 8/16 |
| 凍結・未調整 32 件 | 52,604,232 | 47,399,232 | 17/32 |

未調整の絶対点は 9.89% 減、残り 15 件は同点。
全 96 実行で、候補内部の差分計算、独立の正方形境界ビット集合、
公式 `vis` の値が一致しました。最大壁時間は CPU 7 固定で
0.090 秒未満。この固定列版は `-DAHC031_NO_ALIGNMENT`、
一列の基準版は `-DAHC031_SINGLE_STRIP` で再現できます。
既定は後述の横壁を揃える追加版です。

## 本番の物差し

絶対点は 1 + 面積不足合計 × 100 + 内部の壁の変更長。
初日の壁は無料、同じ日の辺は重複しても一度だけ数えます。
制限 3 秒・1,024 MiB。公式相対点は
`round(10^9 × ケース別の非負最小絶対点 / 自分の絶対点)` を
2,000 件合計します。不正ケースは比較の基準値から除き 0 点です。

[AtCoder 公開の順位ビューア](https://img.atcoder.jp/ahc_standings/index.html?contest=ahc031)の
[得点 CSV](https://img.atcoder.jp/ahc_standings/ahc031/result.csv)
（SHA-256 `3bc6bdaf8e6e259a4b80a5e45cfde40ff63349ce7a72cbba07cca24f88245fea`、
1,059 人 × 2,000 件）から上式を整数で再集計した 1 位は
**1,722,250,219,489 点**（saharan）。上位 3 人の順序は
[公式結果](https://atcoder.jp/contests/ahc031/results/json)と一致します。
[ケース対応表](https://img.atcoder.jp/ahc_standings/ahc031/input.csv)の
2,000 シードは [公式シード](https://img.atcoder.jp/ahc031/seeds.txt)
（SHA-256 `16f021f46aad43a81ad05ebf38ed2b6ac813eafacbb6ad98549832218314db8f`）
と順序も一致。本番評価は下の「凍結した横壁合わせ版の本番再採点」を参照。
上記 A/B の値は相対点ではありません。解説や他の提出は参照していません。

## 再現と次の実験

公式 zip SHA-256:
`20ca7cfc237ddd37a2ec5cffcaa126b3b47fa1e1d2bd99cfe15066e05e3315fc`。
`cargo build --release --locked --bin gen --bin vis` の生成物を指定します。

```bash
bash problems/ahc031/run.sh build/ahc031 "$gen" "$vis" 7
```

C++23 で単一ファイルをビルドし、通常版と同じ 166,877 点を
未調整集合の一件で公式確認しました。座標を別方向の壁から引く
部分共有と、内部の重複した壁を一度だけ数えることを手計算でも検査。
既存 [`interval-union.hpp`](../../library/interval-union.hpp) は任意の
半開区間を扱えますが、この構造の評価は幅全体の横壁が一致するか
だけで足りるため、毎候補で行ごとの区間を生成せず、整列済みの
座標を直接マージしています。構造に依存するため汎用化していません。

次は、固定列内で余剰高さの末尾への集中をやめ、割当面積を保ったまま
前後日に共通の横壁を残します。同じ列配置のまま比較し、減った壁長と
面積不足の増減を別に記録します。

## 固定列の横壁を前後日と揃える追加実験（採用）

同じ固定列構造で、日ごとに前後日の横壁座標を得点化します。
不足していた区画には変更前の高さを、充足していた区画には必要な
最小の高さを確保します。残りの高さを配分する区切り位置を
累積余裕の DP で求め、前後日との一致数が増える場合だけ変更。
4 回以下の前後往復で同じ処理を繰り返し、改善が止まれば終了します。
列幅と予約の所属列、面積不足が増えないことは別の検査でも確認しました。
これは元の解に後処理を追加した比較で、等時間ではありません。

| 新規独立生成 | 固定列 | 横壁合わせ | 横壁合わせ勝ち |
|---|---:|---:|---:|
| 開発 14 件 | 34,297,746 | 32,175,098 | 12/14 |
| 凍結後・未調整 30 件 | 60,609,480 | 52,948,706 | 25/30 |

未調整で絶対点は 12.64% 減り、残り 5 件は同点。面積不足ペナルティ
31,090,500 は不変で、壁の変更費用だけが 29,518,950 → 21,858,176。
全 88 実行で内部・独立・公式の点数が一致しました。
CPU 7 固定の最大壁時間は 0.122 秒未満、
C++23 の単一ファイルも 48,337 点で通常版と一致しました。
この追加実験の設計・調整には本番入力を使っていません。

```bash
bash problems/ahc031/run_align.sh build/ahc031-align "$gen" "$vis" 7
```

採用したバイナリの SHA-256:
`01ccc00a51902bce9216babd0b580b05934071ad77140b56b7f9993ff6e6129d`。
既存の区間和・差分計算で壁を数えられても、最小高さを満たす座標の
最適化や復元はできなかったので、
[`maximize_ordered_cut_reward`](../../library/ordered-cut-placement.hpp)
を追加しました。[使用例](../../examples/ordered_cut_placement_usage.cpp) と
[1,200 件の全列挙比較](../../tests/ordered_cut_placement_test.cpp)。
次は、余った高さの配分だけでなく、需要が窮屈な日に列幅を局所的に
変え、増える縦壁費用と減る面積不足を同じ採点式で評価します。

## 凍結した横壁合わせ版の本番再採点

横壁合わせ版の凍結コミット `57d03b87610eb7e918968301a3b567fdc9d6548a`
（公開版 `fb4acc4255f313b63cc46c95b3965fc983b2d528`）を
公式本番シード 2,000 件で再実行しました。公式ジェネレータに
パラメータ上書きを指定せず、`-v` で出した `file,seed,D,N,E` が
[公式ケース対応表](https://img.atcoder.jp/ahc_standings/ahc031/input.csv)
と全行一致しました。主入力の面積からも `E` を再計算して照合。
当時の採点用ファイルのハッシュは公開されていないため、
これは公式公開データとツールによる再現で、AtCoder への提出ではありません。

全 2,000 件で合法、絶対点が公式 `vis`・独立再生・C++ の評価と一致。
絶対点の和は 2,612,093,134、最大壁時間は 0.143 秒未満（CPU 7 固定）。

| 相対点の比較条件 | 自分の得点 | 1 位 saharan | 自分の順位 |
|---|---:|---:|---:|
| 公開 1,059 人のケース別最小値を固定 | 126,909,397,521 | 1,722,250,219,489 | 399 位相当 |
| 自分を加えた 1,060 人で最小値を計算し直す | 126,909,397,521 | 1,722,250,219,489 | 399 位 |

最小値を更新したケースは 0 件で、共通基準を計算し直しても順位点は
同じでした。同点なし、同一ケース・同一採点式で本番 1 位には **未達**。

```bash
bash problems/ahc031/run_official_audit.sh build/ahc031-audit "$gen" "$vis" \
  seeds.txt input.csv result.csv 7
```

凍結ソースを別ディレクトリに展開してビルドし、バイナリ SHA-256
`01ccc00a51902bce9216babd0b580b05934071ad77140b56b7f9993ff6e6129d`
を確認しました。公開ファイルと生成入力、バイナリ、検査コードの
ハッシュをマニフェストに固定し、同じ構成で中断点から再開できます。
本番ケース別の結果は実装の調整に使っていません。
