# AHC059

[公式問題](https://atcoder.jp/contests/ahc059/tasks/ahc059_a) /
[公式ビジュアライザ・ジェネレータ](https://img.atcoder.jp/ahc059/b8ckwh7N.zip)。
20×20 の盤面から、同じ数字が山札の上で続くと消える規則を使い、
移動を抑えて全 400 枚を取り除きます。

## 同じスタック状態を使って二枚の配置を変える

基準は近いカードから同じ数字の二枚を連続回収し、順序を焼きなましで
改善します。対照・候補とも同じ初期解・20,000 提案を使います。
提案は一対を列から除き、残った列の間に再挿入します。対照は
二枚を同じ隙間に入れ、候補は**同じスタック状態**の二隙間にも
別々に入れます。

残った列は合法な括弧列で、各数字は一度だけ開きます。そのため
途中のスタックは空か、その先頭の数字の祖先列として一意に決まります。
先頭の数字を分類に採用し、同じ分類から選んだ二隙間に一対を入れると、
その間の区間をひとまとまりの合法な回収列として内包できます。
近傍の向きは両方評価し、ときどきランダム挿入して局所解を抜けます。
最後に最短のマンハッタン経路で各カードへ移動し、置く操作は使いません。

| 独立シード | 連続回収の公式点 | 入れ子回収の公式点 | 移動数（連続 → 入れ子） | 勝・負・同 |
|---|---:|---:|---:|---:|
| 開発 14 件 | 206,510 | 211,082 | 23,090 → 18,518 | 14・0・0 |
| 凍結後・未調整 28 件 | 413,250 | 421,321 | 45,950 → 37,879 | 28・0・0 |

未調整で移動数 17.57% 減、公式点 1.95% 増。
全 84 実行で盤面と山札を独立再生し、全消去・操作上限・公式得点・
C++ の移動数が一致しました。CPU 7 で最大 0.172 秒未満。
単一ファイル版は 15,064 点で出力も通常版と同じです。
既定は入れ子版、`-DAHC059_ADJACENT` で連続版です。

既存の `ordered-pair-insertion.hpp` は順番だけの制約で、異なる
スタック状態の二隙間を排除できません。この用途では分類ごとに
左側の最小増分を管理する
[`class-constrained-pair-insertion.hpp`](../../library/class-constrained-pair-insertion.hpp)
を追加しました。[API と使用例](../../docs/LIBRARY_REFERENCE.md#class-constrained-pair-insertion)
および[非対称コスト 10,000 件の全再計算比較](../../tests/class_constrained_pair_insertion_test.cpp)
があります。既存ヘッダの参照先は開いていません。

次は一対だけではなく、平衡な部分列全体を別の隙間へ移す近傍を試し、
同じ追加予算の一対再挿入と比べます。

## 本番比較と再現

得点は全消去なら `N²+2N³−移動数`、残りがあれば `N²−残り枚数` の最大化。
操作は最大 `2N³`。本番は 150 ケースの和、2 秒・1,024 MiBで、
不正・時間超過は全体が 0 点、終了後のシステムテストはありません。
[公式結果](https://atcoder.jp/contests/ahc059/results/json)の 1 位は
chokudai ですが点数は載っていません。

[対応する入力表](https://img.atcoder.jp/ahc_standings/ahc059/input.csv) は HTTP 403。
公式ツールの同梱 100 種と本番 150 ケースの同一性も不明なため **未判定** です。
外部の解法・参加者の提出は使っていません。
