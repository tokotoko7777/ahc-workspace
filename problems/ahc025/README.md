# AHC025

[公式問題](https://atcoder.jp/contests/ahc025/tasks/ahc025_a) /
[公式 Rust ジェネレータ・対話テスタ](https://img.atcoder.jp/ahc025/tNvZmDfV.zip)。
天秤で重さが比較できるだけのアイテムを、D 個の均等なグループへ分けます。

## Ａ/Ｂ

基準版は、予算内の比較で全バケット間の順序を得て、公式生成分布の
打ち切り指数分布から各バケットの代表的な重さを推定します。
推定値の大きいものから最軽量グループに入れ、推定分散を減らす交換を
計算します。重さの真値は読まず、比較の応答だけを読みます。

比較移動版は、クエリ数に応じて一部をグループの比較に残します。
重いグループ A、軽いグループ B から交換候補 x∈A、y∈B を取ります。
順位の異なるバケットなら x が y より重いことが確認済みです。
さらに `A−{x} >= B−{y}` を比較し、差分の移動が元の重量差以下の
場合のみ交換します。持ち替え後の 2 組の重さは元の 2 組の間に収まり、
この操作自体で実分散は増えません。片方だけの移動も同様に検査します。
空集合との厳密な比較が必要なら正の重さから推論し、秤には送信しません。
どちらも使い切れないクエリは合法な単点比較で埋め、必ず Q 回送ります。

| 新規共通入力 | 基準版の絶対点合計 | 比較移動版 | 比較移動版勝ち |
|---|---:|---:|---:|
| 開発 16 件 | 81,154,845 | 42,766,854 | 14/16 |
| 凍結後・未調整 32 件 | 136,670,998 | 77,452,712 | 23/32 |

絶対点は小さい方が良く、確認集合では合計を 43.3% 減らしました。
一方、確認中の `2≤Q/N<3` の 5 件は計 34,640,696→40,878,960 と悪化。
この確認集合を使って条件分岐を調整していません。次の新規集合で
低予算の使い方を比較します。

全 96 実行で、Q 行の合法で重複のない対話と最終分割を独立に検査し、
整数丸め後の絶対点が公式テスタと一致しました。CPU 7 固定のテスタ込み
最大壁時間 0.049 秒未満。比較移動版は初回の作業ブランチ既定です。
凍結バイナリ SHA-256:
`023d50d7f1ee4bc6d81a5dc6abe3f7d63ae0dc912d1b2e033f6a6c0d58afc525`。

## 本番順位との比較

各ケースの絶対点は `1+round(100×グループ重量の母標準偏差)`。
本番 5,000 件でこの絶対点の順位を比較し、同点は同点人数を半分ずつ
数え、上位人数を `r`、提出者数を `n_submit` とします。
問題文の順位点は `round(10^9×(1−r/n_submit))` ですが、
[2023-10-23 の公式告知](https://atcoder.jp/contests/ahc025/clarifications?lang=ja)
によると、実際の本番の係数は **10^8** でした。AtCoder は係数を
直しても順位が変わらないことを確認し、得点をそのまま残しています。
[AtCoder 公開の最終順位ビューア](https://img.atcoder.jp/ahc_standings/index.html?contest=ahc025)の
[得点 CSV](https://img.atcoder.jp/ahc_standings/ahc025/result.csv)
（SHA-256 `3656f77a7b2c5c59e1e1e78d39eeb5c47d89f830e24d708da2beba914ec1dbeb`）
は、1,085 人 × 5,000 ケース、`rank_min,100000000` です。
公式どおり再集計した 1 位は **492,832,027,444 点**（eijirou）。
[公式結果](https://atcoder.jp/contests/ahc025/results/json)の上位順とも照合できます。

[公式本番シード](https://img.atcoder.jp/ahc025/seeds.txt) 5,000 件は
SHA-256 `8a39261299bef0387172c0e0c4523c49b0cb993efd4f702ec7cf5124cf5b4c55`
と一致。上の A/B とは重複しません。
[ケース対応表](https://img.atcoder.jp/ahc_standings/ahc025/input.csv) と
シードの並び、ファイル番号、公式生成器が出した `N,D,Q` を全件照合しました。
シードのみ指定して生成し、パラメータを上書きしていません。
実行時間 2 秒・メモリ 1,024 MiB、本番の非 AC ケースは順位点 0 です。

初回比較移動版の凍結コミット
`c8c587f292af7ba03ef6a2b94e95be5f56a7e8a0`（公開版 `21034a64`）を
公式の 5,000 ケースで再採点しました。全件合法で、計 3,498,575 回の
比較と絶対点が公式テスタと独立再生で一致。絶対点の和は
10,690,694,272、テスタ込み最大壁時間は 0.419 秒未満（CPU 7 固定）です。

| 比較方法 | 自分の順位点 | 1 位の順位点 | 自分の順位 |
|---|---:|---:|---:|
| 公開 1,085 人の分布を固定した参照値 | 354,364,239,662 | 492,832,027,444 | 314 位相当 |
| 自分を追加した同じ 1,086 人で全員再集計 | 354,498,342,544 | 492,836,970,699 | 313 位 |

非 AC の参加者も分母に残し、当該ケースの順位点は 0。固定参照で
自分は過去の参加者に含まれないため、過去の同点者を全員数えます。
全員再集計でも 1 位は eijirou のままで、同一条件の比較で **未達**。
AtCoder への提出結果ではありません。公式シード・採点列の対応と
公開ツールで再現した結果で、元の入力ファイルのハッシュは非公開です。
本番の個別結果は調整に使用せず、低比較予算を変更した版は未評価です。

```bash
bash problems/ahc025/run_official_audit.sh build/ahc025-audit "$gen" "$tester" \
  seeds.txt input.csv result.csv 7
```

初回の凍結ソースを `git archive` で別ディレクトリに展開して
ビルドしました。同じ g++ 14.2.0 / C++23 で、バイナリ SHA-256 は上記の
凍結版と一致しました。スクリプトは公式のツール、シードと
CSV ファイル、生成入力と実行バイナリの情報をマニフェストに残し、
同一の構成なら中断点から再開できます。

## 再現とライブラリ

公式 zip の SHA-256:
`ac864127f401f74403a464f45d4188ba65e5caa680ab42e2f14bd6824710fdfe`。
`cargo build --release --locked --bin gen --bin tester` でビルドし、
両実行ファイルの絶対パスを指定します。

```bash
bash problems/ahc025/run.sh build/ahc025 "$gen" "$tester" 7
```

C++23 の提出用単一ファイルも生成して対話テストできます。
通常のソートでは比較回数を予測しにくく、途中で打ち切ってもバケット間の
位置関係が保証できないため、
[`budgeted-order-buckets.hpp`](../../library/budgeted-order-buckets.hpp)
を追加しました。[使用例](../../examples/budgeted_order_buckets_usage.cpp)、
[1,200 ランダム入力のテスト](../../tests/budgeted_order_buckets_test.cpp)、
[ライブラリ仕様](../../docs/LIBRARY_REFERENCE.md#budgeted-order-buckets)。

次は、低予算では順位推定を優先し、完全な次のバケット分割が
できず余った比較だけでグループを調整する版を、新しい低予算ケースを
多く含む集合で比較します。

## 低比較予算で順位推定を優先する追加実験（未採用）

`2 ≤ Q/N < 3` ではグループ比較の枠を先に予約せず、完全なバケット分割を
続けられる限り単点比較に使い、余りだけで分散が悪化しない交換を試しました。
`Q/N≥3` では変更なしです。低予算の 5 種類の `N,D,Q` と、変更しない
1 種類を公式ジェネレータで固定し、独立シードで三つの版を比較しました。

| 新規の `2≤Q/N<3` の入力 | 従来の予約版 | 順位優先＋余りで交換 | 順位だけ |
|---|---:|---:|---:|
| 開発 15 件 | 94,928,746 | 143,885,092 | 155,077,298 |
| 凍結後・未調整 30 件 | 197,259,539 | 336,043,600 | 364,972,714 |

未調整 30 件では、順位優先版は順位だけより改善しましたが、従来版には
2 件しか勝てませんでした。初回の未調整集合にあった低予算 5 件での
傾向を新しい集合で再現できず、従来の予約版を既定に残します。
`Q/N≥3` の未調整 6 件は、従来・順位優先版とも合計 35,013,826 点で、
全ケースの得点が同じでした。全 162 実行で正確に Q 回の合法な比較を
行い、公式テスタと独立検査が一致。テスタ込み最大壁時間は 0.038 秒未満
（CPU 7 固定）。C++23 単一ファイルでも 163 回の比較と 8,756,965 点を
確認しました。追加実験の本番評価はしていません。

```bash
bash problems/ahc025/run_lowq.sh build/ahc025-lowq "$gen" "$tester" 7
```

次は、クエリ数の一律の割合だけでなく、未確定バケットから作る初期分割が
どの組で大きく不確かかを見て、その組を先に比較します。単点の順位を
もう一本精密化するより、分割の誤差を直接減らせるケースがあるかを、
同じ比較回数で別の低予算集合により確認します。
