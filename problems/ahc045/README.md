# AHC045

[公式問題](https://atcoder.jp/contests/ahc045/tasks/ahc045_a) /
[公式 Rust ジェネレータ・対話テスタ v2](https://img.atcoder.jp/ahc045/jOO09LxU_v2.zip)。
座標が矩形範囲でしか分からない都市を指定人数のグループに分け、
各グループ内を短い道路で接続します。

## 同じ質問とグループで、道路の推定だけを比較

両版は矩形の中心を Hilbert 順に整列し、向き・グループ順の
16 通りから中心距離による最小全域木の合計が短い分け方を選びます。
質問の上限内の小グループは全体の木を質問し、大きなグループは
近傍集合を作って、質問にまだ少ししか出ていない都市を優先します。
基準版は大きなグループの質問で得た辺の中心距離を 0.87 倍に
し、座標範囲から分かる下限で切り上げます。

候補版はさらに、質問の木に含まれない辺が、木でその端点を結ぶ経路の
どの辺よりも短くないことを用います。推定がこの順序を逆にして
いる時は、矩形から計算した可能距離の範囲内で二値を動かし、
12 パス反復してから、大きなグループの木を作り直します。
真の座標を推定モデルへ渡すことはありません。
基準・候補のグループと全質問が同じであることを照合しました。
候補が同じ質問への追加計算を行う設計で、等時間比較ではありません。

| 新規独立シード | 選ばれた辺の割引のみ | 順序関係も使う | 順序版の勝ち |
|---|---:|---:|---:|
| 開発 14 件 | 4,360,242 | 3,625,385 | 13/14 |
| 凍結後・未調整 28 件 | 8,123,736 | 6,910,990 | 26/28 |

未調整の道路長は 14.93% 減少し、残り 2 件は同点。
未調整の質問数は両版とも 7,399 回でした。
全 84 実行で質問の上限、全都市の一意な所属、木の連結性、距離の
整数切り捨てを独立に検査し、公式テスタの点と一致しました。
公式テスタ込み最大壁時間は 0.144 秒未満（CPU 7 固定）。
順序版を既定にし、`-DAHC045_DISCOUNT_ONLY` で基準にできます。

## 本番の物差し

絶対点は真のユークリッド距離を辺ごとに切り捨てて足した値で、
小さい方が良いです。制限は 2 秒・1,024 MiB、質問は 400 回以下、
一度に 2〜L 都市。本番は
`round(10^9×ケース別最小絶対点/自分の絶対点)` の 3,000 件合計です。
非 AC はケース得点 0、最小値の対象外です。

[AtCoder 公開の順位ビューア](https://img.atcoder.jp/ahc_standings/index.html?contest=ahc045)の
[得点 CSV](https://img.atcoder.jp/ahc_standings/ahc045/result.csv)
（SHA-256 `126880ede7e13358d79d5217c5c0fbcbd0d069bed868af1df62a3a93c38dcaaf`、
1,299 人 × 3,000 件）を再集計すると、1 位は
**2,988,855,588,054 点**（nikaj）。上位 3 人は
[公式結果](https://atcoder.jp/contests/ahc045/results/json)と一致します。
[入力対応表](https://img.atcoder.jp/ahc_standings/ahc045/input.csv) と
[公式シード](https://img.atcoder.jp/ahc045/seeds.txt) は順序も全件一致。

## 再現とライブラリ

公式 zip SHA-256:
`dfaab9fa13032ab4fd60211ac9194dbdfbaa416e0799d834bb75ac4551e47e03`。
`cargo build --release --locked --bin gen --bin tester` で用意します。

```bash
bash problems/ahc045/run.sh build/ahc045 "$gen" "$tester" 7
```

基準・候補とも C++23 単一ファイルで公式採点を確認し、
同じ入力で通常版と同じ 214,016 / 206,307 点でした。
[Hilbert 順](../../library/hilbert-order.hpp) は既存部品を利用。
既存 [Kruskal](../../library/kruskal.hpp) では完全グラフの辺を列挙して
ソートする必要があるため、距離行列を直接読む密な Prim を使いました。
推定値の部分順序を近似的に満たす部分は
[`project_bounded_order`](../../library/bounded-order-projection.hpp)
として切り出しました。[使用例](../../examples/bounded_order_projection_usage.cpp) /
[1,500 件の単一制約の全列挙と連鎖テスト](../../tests/bounded_order_projection_test.cpp)。
次は質問の後に都市を同じ人数のまま近いグループ間で交換し、
元の分け方の候補では使えなかった比較情報を活かせるか検証します。

## 質問後に人数を保って交換する追加実験（未採用）

質問は順序版と全く同じです。グループ全体の真の最小全域木を聞いた
グループは固定し、それ以外の二つのグループで近い都市を 1 つずつ
交換します。両グループの推定最小全域木を引き直し、
補正距離による和が減った場合にだけ交換を採用します。
最大 8,192 提案、二つのグループの頂点数の二乗和の累計 2,600 万、
650 ms のいずれかで追加処理を止めます。質問予算は同じですが、
交換には計算を追加するため、等時間の比較ではありません。

| 新規独立シード | 順序補正だけ | 順序補正 + 交換 | 交換の勝ち / 負け / 同点 |
|---|---:|---:|---:|
| 開発 14 件 | 3,217,709 | 3,207,876 | 9 / 5 / 0 |
| 凍結後・未調整 28 件 | 7,136,780 | 7,224,355 | 16 / 11 / 1 |

未調整の中央値は −954.5 でも、道路長の合計は 1.23% 悪化。
質問で比較していないグループ間の道路を、交換により過大評価している
可能性がありますが、原因と断定できないため次の仮説に留めます。
既定は順序補正だけのまま、交換を `-DAHC045_POST_QUERY_SWAP` で
切り替えられるようにしました。

全 84 実行で合法かつ公式テスタ・独立再生一致、未調整の質問は
両版とも 7,795 回で全質問が一致しました。テスタ込み最大壁時間
0.211 秒未満（CPU 7 固定）。C++23 単一ファイルも同じ 209,529 点。
本番を調整に使っていません。次は候補境界の不確かな辺を含む
質問を一部に割り当て、グループ交換が依存する辺を直接比較します。

```bash
bash problems/ahc045/run_swap.sh build/ahc045-swap "$gen" "$tester" 7
```
