# AHC074

[公式問題](https://atcoder.jp/contests/ahc074/tasks/ahc074_a) /
[公式 Rust ジェネレータ・テスター](https://img.atcoder.jp/ahc074/YAAu43G9.zip)。
64 窓、192 枚の紙で、全 1,024 注文をオンライン処理します。
着手時の `main` と問題別ブランチに既存実装はなく、基準から新規実装しました。

## 単一ビットの切替と、複数窓を埋める接頭辞紙

基準は窓ごとに、その窓だけに 0/1 を印刷した紙を各一枚置きます。
表示が違う場合に、見えている紙を同じ窓のもう一枚の下に移します。
余った紙は穴だけです。従ってどの注文にも誤答せず、最大 64 手で対応できます。

候補は残り 64 枚を、初期に与えられた全 256 種のカタログから選びます。
右端の窓をアンカーにし、それ以前の窓へ接頭辞を印刷します。
十分長く一致する右端区間をカタログ全体で増やすよう、
アンカー・印刷する品目を貪欲に選びます。注文列は設計時に読みません。

注文ごとに右端の窓でその紙を選べるよう、先行する紙を
可視な状態で一枚ずつ、選んだ紙の直後へ移します。
紙の右側が目標と一致する区間では、その区間の最初の窓の紙より前へ
一度だけ動かせば複数窓を同時に変更できます。左側の未処理窓は
さらに前の紙が覆うため、その場では上書きしません。
単一窓での切替と、こうした連続区間を使う場合の推定操作数から
区間分割 DP を作り、右の区間から実行します。
持ち上げた接頭辞紙は自分のアンカーから見え続けるので、
次の異なる注文の前に元のアンカー群へ戻せます。
全操作で可視性・再挿入位置を検査しています。

| 独立シード | 単一ビットのみ | 接頭辞紙あり | 候補の勝ち |
|---|---:|---:|---:|
| 開発 14 件 | 459,389 | 360,721 | 14/14 |
| 凍結後・未調整 28 件 | 918,184 | 724,334 | 28/28 |

未調整の操作数は 21.11% 減。全注文が正しく、絶対点は操作数と同じ。
全 84 対戦の公式テスター・独立した全操作再生・C++ の得点が一致し、
CPU 7 固定でテスター込み最大 0.092 秒未満でした。
C++23 単一ファイルも 25,721 点で、全操作が通常版と一致しました。
接頭辞版を既定とし、`-DAHC074_BIT_ONLY` で単一ビット版を再現できます。

既存の `sequence-overlap.hpp` は一般の列の重なり用で、固定長の
カタログ、アンカーの可視性、戻し費用を含まないため、
64-bit マスクの一致判定と区間 DP は問題側に置きました。

## 本番比較

絶対点は `384×誤注文数+操作数` の最小化。本番順位点は
各ケースで小さい絶対点の人数と同点の半数を使い、
`round(10^9*(1-(n_lose+0.5*n_tie)/n_submit))` を合計します。
本番 2,000 ケース、2 秒・1,024 MiB、無効ケースの順位点は 0。
[公式部門説明](https://atcoder.jp/contests/ahc074/division)では
Human Only と With AI は別順位表です。
[公式結果](https://atcoder.jp/contests/ahc074/results/json)では
`Division=1` の 1 位は noimi、`Division=2` の 1 位は mech_39。
両部門の 1 位を同順位・同点と見なすことはできません。

[公式本番種](https://img.atcoder.jp/ahc074/seeds.txt)は
公開 SHA-256 `9562a1597447a1116b5b4b869d74b3598ce13bc33b1ed8bd9ac1ee9df33d92e7`
と一致します。一方、[得点 CSV](https://img.atcoder.jp/ahc_standings/ahc074/result.csv)と
[入力対応表](https://img.atcoder.jp/ahc_standings/ahc074/input.csv)は HTTP 403。
両部門の公式数値と参加者ごとのケース基準が確認できず、
本番 1 位比較は **未判定** です。公開本番種は開発・検証には使っていません。

## 追加実験: カタログ上で紙の置換を厳密に試す

初回の紙から、同じアンカーの接頭辞紙を別の品目の紙へ交換します。
最大 64 提案ずつ、各提案で単独最長区間のカタログ近似と、
カタログ全 256 品目をランダムな順で一回ずつ表示した実操作数を
どちらも計測します。乱数は固定で、本物の注文列はまだ読みません。
対照は初回と同じ近似の改善、試験版は実操作数の減少で受理します。

| 新規独立シード | 近似で受理した操作数 | 実操作数で受理した操作数 | 勝・負 |
|---|---:|---:|---:|
| 開発 14 件 | 360,647 | 359,790 | 8・6 |
| 凍結後・未調整 28 件 | 721,543 | 722,521 | 12・16 |

近似で選ぶ方式は初回と 42 件すべて同点でした。実操作数を使う方式は
未調整で操作数が 978 手増えたため不採用。初回を既定のままとし、
`-DAHC074_REFINE_PROXY` と `-DAHC074_REFINE_EXACT` を比較できます。
両比較の全 168 対戦は誤注文ゼロで公式・独立・C++ が一致、
CPU 7 固定で最大 0.266 秒未満でした。試験版の単一ファイルも
25,337 点・全出力が一致しました。

```bash
bash problems/ahc074/run_refine.sh build/ahc074-refine "$gen" "$tester" 7
```

一つのカタログ順で計った改善は、紙の前後関係が変わる本物の注文に
そのまま持ち越せませんでした。次は二つ以上の独立に並べ替えた
カタログ順で改善が再現する提案だけを残す方法と比較します。
両部門の公開本番順位点は引き続き未判定です。
