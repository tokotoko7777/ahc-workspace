# AHC043

[公式問題](https://atcoder.jp/contests/ahc043/tasks/ahc043_a) /
[公式 Rust ジェネレータ・ビジュアライザ](https://img.atcoder.jp/ahc043/de43f43a9c.zip)。
駅を自宅と職場の近くでつなぎ、運賃を集めて余剰資金を最大化します。

## 初期の一路線から、資金と収益を見て駅を追加する

基準は自宅・職場の半径 2 に入る駅のペアへ運賃を集計し、
初期資金で建設できる最短路 1 本と待機だけの中で最終資金が最大の案を
選びます。駅が稼ぎ始めるまでの建設ターンを含めます。

候補はその同じ路線から、既存駅からの空きマスの最短経路を使った
延伸と、既存線路を駅へ変更する追加を比較します。
全駅は一つにつながっているため、各人の自宅と職場に駅があるかの
二条件で新しい収益を評価できます。現在の収入で各工事費を
払えるまでの待機を正確に数え、追加費用を差し引いても
終了時資金が最も増える追加だけを繰り返します。
一本道に追加処理を行う比較であり、等時間ではありません。

| 新規独立シード | 一路線での最終資金 | 駅を追加 | 追加の勝ち |
|---|---:|---:|---:|
| 開発 12 件 | 1,170,308 | 38,157,357 | 11/12 |
| 凍結後・未調整 24 件 | 2,236,615 | 63,926,853 | 24/24 |

未調整で合計は 28.58 倍。一方でこれらは絶対点の単純合計で、
本番相対点ではありません。全 72 実行で 800 回の操作、
工事直前の残高、線路の方向別連結、運賃を独立に再生し、
公式 `vis` と C++ の値が一致。CPU 7 固定で最大壁時間 0.058 秒未満。
C++23 単一ファイルも同じ 4,682,737 点でした。
駅追加を既定とし、`-DAHC043_ONE_LINE` で一路線版を再現できます。

## 本番比較

最終資金を最大化。制限は 3 秒、1,024 MiB、800 ターン固定。
相対点は各ケースの `round(10^9×自分の絶対点/ケース別最大絶対点)`
の 2,000 件合計。非 AC は 0 点で、最大値の計算からも除外されます。
最大値 0 の場合の AC は 10^9 点ですが、公開表では全ケース最大値が正です。

## 再現とライブラリ

公式 zip SHA-256:
`be1de3e41c6a1b6897a2825635fc308b72b3b434f71a440599b09c32fb16bd70`。
`cargo build --release --locked --bin gen --bin vis` で用意します。

```bash
bash problems/ahc043/run.sh build/ahc043 "$gen" "$vis" 7
```

既存の [CoverageCounter](../../library/coverage-counter.hpp) は一条件でも
加点する部品で、自宅と職場の両条件が必要な場合を扱えません。
[`PairedCoverageReward`](../../library/paired-coverage-reward.hpp) として、
追加前の差分評価と重複しない加算を切り出しました。
[使用例](../../examples/paired_coverage_reward_usage.cpp) /
[30,000 回の全再計算比較](../../tests/paired_coverage_reward_test.cpp)。
次は、一路線として資金が最大の初期位置だけでなく、早く稼働する案や
周囲の駅追加で開通しやすい案も先に選び、その後の工事を比較します。

## 初期駅を変えたときの効果（既定変更なし）

同じ初期駅ペアで線形だけを変える対照と、
初期駅も分散させる版を、どちらも最大 8 回の完成シミュレーションで
比較しました。最初の 2 回は同じ最良初期ペア・二つの向きです。
残りは将来駅にできるマスを増やすよう、マンハッタン最短路の
折れ方を DP で変えます。初期駅も分散する版は、早く資金を回せるか、
片方だけ駅がある通勤需要が多いか、両駅の駅勢圏が大きいかでも
初期ペアを選びます。各案は従来と同じ延伸・採点で完成させます。
売上の増え方が違えば回数内の延伸数は違いますが、上限 8 回と
2.45 秒の期限は共通で、全測定で時間上限には達していません。

| 新規独立シード | 同じ初期駅で形のみ変更 | 初期駅も分散 | 勝ち / 負け / 同点 |
|---|---:|---:|---:|
| 開発 12 件 | 35,313,042 | 35,555,774 | 5 / 4 / 3 |
| 凍結後・未調整 24 件 | 49,972,611 | 52,340,760 | 12 / 4 / 8 |
| 同じ凍結版の別確認 20 件 | 42,956,058 | 43,627,334 | 7 / 9 / 4 |

未調整 24 件では +4.74%、最大の改善ケースを除いても +980,728。
別確認は +1.56% でも負けが勝ちより多く、最大の改善ケースを除くと
−257,693。再現性が十分でないので既定を変更せず、
`-DAHC043_SEED_PORTFOLIO` と `-DAHC043_GEOMETRY_CONTROL`
で切り替えられるようにしました。本番入力は生成・評価していません。

全 112 実行で合法の 800 操作と、公式・独立・C++ の資金が一致。
最大壁時間 0.310 秒未満（CPU 7 固定）。C++23 単一ファイルでも
6,325,738 点で通常版と一致しました。

```bash
bash problems/ahc043/run_seed_portfolio.sh build/ahc043-portfolio "$gen" "$vis" 7
```

次は開始駅の静的な評価をさらに増やすより、その駅から 1〜2 駅目を
実際に増設する部分シミュレーションで、資金回復が早い案を選びます。
今の試行では仮の駅勢圏を評価するためネットワークを複製しており、
同じ試行を増やす場合は静的な盤面情報と変更される収益状態を分離します。
