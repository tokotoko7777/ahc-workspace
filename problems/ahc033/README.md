# AHC033

[公式問題](https://atcoder.jp/contests/ahc033/tasks/ahc033_a) /
[公式 Rust ジェネレータ・ビジュアライザ](https://img.atcoder.jp/ahc033/ELSlXTEw.zip)。
5×5 のヤードに搬入されるコンテナを、番号ごとに決まった出口へ
順番通りに搬出します。

## 直列搬出と並列の初動

基準版は小クレーンを最初に撤去し、大クレーンだけで作業します。
次に出すべきコンテナが既に見えていれば、現在位置・コンテナ・
出口を結ぶ距離が最短のものを選びます。すべて隠れているときは、
搬入口の先頭を空いている中間区画に移します。中間区画が満杯なら、
見えている最小番号を正しい出口へ出し、順序のペナルティを払ってでも
作業を進めます。各荷物の一時置きは最大 1 回です。

候補版では初動だけ複数台を使います。任意の行集合で各行の先頭 1 個を
並列に取り出すパターンと、全行の先頭 1 個に加え任意の行集合で
2 個目まで取り出すパターンを試します。各クレーンは自分の行だけを
進み、2 個出す行は遠いセルから埋めるため、積荷を持って置かれた
コンテナを乗り越えません。初動の後は小クレーンを撤去して
同じ直列搬出に合流し、直列のみを含む全 63 案の最良を残します。
同等の時間予算の比較ではなく、構造と初期条件を増やした比較です。

| 公式生成器による新規入力 | 直列のターン合計 | 並列初動 | 並列初動の勝ち |
|---|---:|---:|---:|
| 開発 16 件 | 5,411 | 4,870 | 16/16 |
| 凍結後・未調整 32 件 | 10,813 | 9,754 | 32/32 |

未調整のターン合計は 9.79% 減少。全 96 実行で全コンテナを正しい出口へ
順番通りに搬出し、内部得点・独立再生・公式 `vis` が一致しました。
CPU 7 固定で最大壁時間 0.008 秒未満。後述の追加版が作業ブランチの既定です。
`-DAHC033_ORIGINAL_PREFIX` でこの並列初動版、
`-DAHC033_SERIAL_ONLY` で直列版に切り替えられます。

## 本番の物差し

絶対点はターン数 + 正しい出口での転倒数 × 100 + 誤搬出数 × 10,000
+ 未搬出数 × 1,000,000 で、小さい方が良いです。3 秒・1,024 MiB。
本番は `round(10^9×ケース別の最小絶対点/自分の絶対点)` の 2,000 件合計。
無効なケースは相対点 0、比較基準からも除外します。
[公式シード](https://img.atcoder.jp/ahc033/seeds.txt) は 2,000 件、
SHA-256 は `502228d18e6d0d00f92654ad85f13945fc1d2865f69df352aee061a53ebf3cfa`
で問題文の記載と一致。開発・確認シードとは重複しません。

[公式結果](https://atcoder.jp/contests/ahc033/results/json) で 1 位は
bowwowforeach と確認しましたが、相対点は載っていません。
[公開得点 CSV](https://img.atcoder.jp/ahc_standings/ahc033/result.csv) と
[ケース対応表](https://img.atcoder.jp/ahc_standings/ahc033/input.csv) は
どちらも HTTP 403 でした。本番の 1 位の値とケース別の最小値を
確認できず、本番ケースは生成・評価していないため **未判定**です。
外部の解説や提出は参照していません。

## 再現と次の実験

公式 zip の SHA-256:
`7ed433050fed2d0eba0794cf7df2898b54f3e17cd6d2904403e86d970e4c7b77`。
`cargo build --release --locked --bin gen --bin vis` で用意します。

```bash
bash problems/ahc033/run.sh build/ahc033 "$gen" "$vis" 7
```

C++23 単一ファイルの出力も合法で、通常版と同じ 307 点。
空くマスへの同時移動を許す一方、交換・重なり、荷を掴んだ小クレーンの
侵入制限、積荷を持ったままの撤去を独立テストで確認しました。
既存 [`grid-bfs.hpp`](../../library/grid-bfs.hpp) は静的な最短経路向けで、
保持する荷、搬入時刻、他車の同時移動は表現しません。この初動では
事前に各行で衝突しない動きに制限し、汎用部品の追加を見送りました。
次は小クレーンを初動直後に全て撤去せず、行内搬送や大クレーンからの
引継ぎを許し、荷物の移動順制約を守りながら並列区間を延ばします。

## 行内で先に搬出する追加実験（採用）

各クレーンの活動範囲を引き続き自分の行に限定し、初動で一時置きだけでなく
正しい次の番号の搬出も選びます。行内で 4 個までの搬送を列挙し、
小クレーンは積荷を持って他のコンテナを越えない案だけを残します。
同じ荷の配置・搬入順・搬出済み範囲・小クレーンの位置に達する案を
まとめ、各行で上位 6 案と未操作案を保持。初動案を組み合わせた
40 パターンを追加し、初回版と同じ直列搬出で最後まで評価します。
追加探索なので等時間比較ではありません。

| 新規独立シード | 以前の並列初動ターン合計 | 行内で早期搬出 | 新版の勝ち |
|---|---:|---:|---:|
| 開発 12 件 | 3,681 | 3,368 | 12/12 |
| 凍結後・未調整 24 件 | 7,384 | 6,867 | 24/24 |

合計で 7.00% 減り、全 72 実行で全荷物を正しい出口に順番通り搬出。
公式 `vis`・独立シミュレーション・C++ の得点が一致しました。
最大壁時間は 0.009 秒未満（CPU 7 固定）。単一ファイルでも同じ
292 点を確認。元の候補を必ず残し、最良点の案を出します。
本番ケースは評価していません。次は通路を独占する行単位の初動を越えて、
異なる行の仕事を時間付きの衝突制約の下で並行させます。

```bash
bash problems/ahc033/run_front.sh build/ahc033-front "$gen" "$vis" 7
```
