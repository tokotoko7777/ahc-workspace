# AHC004: Alien's Genome Assembly

[公式問題文](https://atcoder.jp/contests/ahc004/tasks/ahc004_a) /
[最終順位表](https://atcoder.jp/contests/ahc004/standings) /
[順位・点数のアーカイブ](https://huggingface.co/datasets/SakanaAI/ALE-Bench/blob/main/ahc004.zip)。

本番1位は **7,321,305,762**（上記アーカイブの `ahc004//standings_scores.csv`。
アーカイブ自体のSHA-256は `2c43b467ddfabfa774306c350f397a272f1b4ae6023066a0c44ea93fe62a42c8`）。
公式の丸め済み絶対得点を100回合計して最大化します。各回3秒・1,024 MiBで、
ケースにAC以外があれば提出全体0点です。本番後のシステムテストはなく、配布の
ローカル用 seed 0–99 は本番と異なると明記されています。本番ケースを確認できず、
ローカルで1位相当の値を超えても **1位超えは未判定** とします。

### 候補

- 既存の [独立実装](../../examples/search/ahc004_genome_sa.cpp) を基準として維持。
  部分文字列を盤面に直接置いてから、焼きなましで改善する。
- `AHC_CONTIG_SEED` は、盤面に配置する前に高一致の末尾・先頭の重なりを兼容する順に
  連結し、周期付きの部分パターン候補を作る。各パターンを折り返しと文字の
  一致条件を守って配置し、残りの語は既存の処理で補う。通常の初期解候補も残し、
  初期構築150 ms・探索末尾2,780 msの制限は両者共通。
- 汎用化: 既存の `WeightedDsu` で相対位置は持てるが、合体前に文字の衝突を
  調べるための共通APIがなかったため、[周期付き部分パターンの併合](../../library/circular-pattern-components.hpp)
  を追加した。通常の整数オフセットは内部でそのまま使い、周期を法とする
  判定と文字データの更新をラッパーに分離した。
  [使用例](../../docs/LIBRARY_REFERENCE.md#周期付き部分パターンの併合)、
  [テスト](../../tests/circular_pattern_components_test.cpp)。

### 再現

公式問題文のリンクから入力の zip とツールを取得してください。ツール側で
`cargo build --release --locked` を実行し、下の `TOOLS_DIR` を指定します。
入力と Rust のビルド結果は Git には置きません。

```sh
g++ -std=c++23 -O3 examples/search/ahc004_genome_sa.cpp -o baseline
python3 scripts/bundle.py problems/ahc004/main.cpp -o contig.single.cpp
g++ -std=c++23 -O3 contig.single.cpp -o contig
g++ -std=c++23 -O2 tests/circular_pattern_components_test.cpp -o components_test
./components_test
python3 problems/ahc004/benchmark.py INPUTS_DIR dev --start 0 --end 10 --vis TOOLS_DIR/target/release/vis --entry baseline=baseline --entry contig=contig
python3 problems/ahc004/benchmark.py INPUTS_DIR holdout --start 60 --end 70 --vis TOOLS_DIR/target/release/vis --entry baseline=baseline --entry contig=contig
```

開発10件、候補設計に使わない60–69の未調整10件は実験前に固定しました。
それぞれ同一ケースで旧・新を交互に実行し、公式採点と独立スコア計算で照合します。

| 対象 | 既存の平均 | 合成候補の平均 | 差 | 候補勝ち |
|---|---:|---:|---:|---:|
| ローカル開発 seed 0–9 | 68,623,544.8 | 70,809,483.0 | +2,185,938.2 | 8/10 |
| ローカル未調整 seed 60–69 | 66,275,335.0 | 68,122,402.3 | +1,847,067.3 | 5/10 |

40出力すべて合法で公式採点と独立検査が一致、最大実測2.786604秒。
この作業ブランチでは平均の良かった候補を `main.cpp` の既定にしましたが、
試行数は少なく、未調整では5敗もあります。`-DAHC_BASELINE_SEED` または
元の例で既存方式に戻せます。本番の1位超えは未判定のままです。

次の大きい仮説は、各行を循環シフト・行順変更して横方向の出現を壊さず、
縦方向の語をまとめて増やす近傍です。列側も交互に行い、単語上書きのみの
探索で固定されやすい全行の位相を変えます。対向する全ラインの差分評価が必要な
ため、同一初期盤面・同じ時間で評価し、有効なケースとコストを分けて記録します。

行/列の回転・交換は [同一盤面からの追加探索の診断](experiments/line_cycle/README.md)
に保存しました。新規8件では従来の追加探索に対し3勝5分、平均+140,634.375点。
差分評価のテストを追加し、既定の探索方針は変更していません。

### 実験候補：観測閉路を使う初期盤面（既定は変更しない）

`-DAHC_CYCLE_SEED` を付けた場合のみ、読みの中に実際に出現した
5/6-gram を辺とする de Bruijn グラフから長さ20の閉路を列挙します。
最小回転で重複を除き、実際の読みの包含（長い読みを重視）で順位付けします。
観測辺の組み合わせから偽の閉路も生じるため、元盤面の復元とは見なしません。

まず平行な2行を置き、2箇所の交差が一致する列を探索します。以降も
それまでの交差をすべて維持して1本ずつ追加し、最大7本まで置きます。
通常の短い語の配置で空白を埋め、実際の問題得点で選びます。最初の既存
初期解は必ず評価し、通常の初期化も残します。独立現行版の全探索結果と
比べて常に改善する保証はありません。閉路列挙に8 ms・2万ノード、
配置試行の前処理に各6 msを目安に打ち切り（時計は列挙256ノード・
配置1本ごとに確認）、探索全体の既存目標は同じ2,780 msです。
閉路がない短文中心のケースでは配置を追加しません。

この枝では合成データの閉路・交差・打切りの正しさだけを検証しました。
スコア比較はダウンロードした公式ローカル seed 0–99 の全100件が対象で、
ここでは未計測です。本番比較の条件は変わりません。

```bash
g++ -std=c++23 tests/ahc004_observed_cycles_test.cpp -o /tmp/cycle-test
/tmp/cycle-test
python3 scripts/bundle.py problems/ahc004/main.cpp -o /tmp/cycle.single.cpp
g++ -std=c++23 -DAHC_CYCLE_SEED /tmp/cycle.single.cpp -o /tmp/cycle
```

#### 短い探索での選び直し（対照つき）

公式ローカル100件での初回実験では、観測閉路の初期盤面が通常初期盤面を
上回って選ばれたケースは0件でした。そこで、初期点だけで捨てると
有用な構造まで見落とすかを、次の2腕で比較できます。

- `-DAHC_CYCLE_SCOUT`：通常盤面の最良と、閉路盤面の最良を各120 ms探索。
- `-DAHC_CYCLE_SCOUT_CONTROL`：通常盤面の最良と次点を各120 ms探索。
  診断のため閉路盤面も同じ初期化手順で作って点を記録しますが、採用しません。

両腕で初期化、短い探索の乱数シードと温度、最終終了目標2,780 msは
共通です。持ち時間を過ぎない範囲で、選択対象の生盤面と短い探索後の
盤面を厳密な出現数・空白点で比較し、最良から残り時間を使います。
閉路がなければ両腕とも同じ通常盤面2枚です（次点なしなら同じ盤面）。
stderr に各盤面の初期出現数・空白数、初期探索後の出現数・空白数、
反復数、勝者、実際に閉路を第2枠に入れたかを残します。
時計制御による反復数の揺れは残ります。両腕の品質評価は公式
ローカル seed 0–99 の全100件で行い、この実装段階では未計測です。

#### 交差による幾何の診断（ソルバー未接続）

`anchor-congruence.hpp` は、閉路候補の先頭5本から3本を選び、
1本目の位置と位相を固定して、残る2本の相対位置・位相を全て検査します。
5本が真の行列由来なら少なくとも3本は同方向ですが、復元候補には偽物も
あり得ます。3交点の文字を512通りの署名とし、候補列IDの64 bit集合を
引きます。列数・相異なるID数で枝を落とし、残りは位相が存在する辺の
二部マッチングを厳密に解きます。交差を実際に満たせることと、
生成盤面の復元は同じではありません。

上位の三行候補について、候補列の可能な位相を再列挙し、第四行の1文字を
同時に満たす列だけを残して同じマッチングを実行します。
既知の真の線からランダムに30/34/36本渡した各8合成例では、
三行候補の幅128で2/1/6件、幅768で5/5/7件に真の相対配置を含みました。
幅768で拾えた17件はいずれも第四行を加えたとき真の四行が1位。
幅768のCPU 5実測平均は三行探索で約56–64 ms、第四行で約412–473 ms
（合計およそ0.47–0.54秒）。18 ms制限では三行の再現率が低く、そのまま
採用しません。合成例は偽閉路を混ぜていないため実データでの再現率は未確認。
偽閉路・候補少数時への対策と列の実配置は今後の課題です。順位・得点は
測定しておらず、提出用ソルバーの動作も変えていません。

```bash
g++ -std=c++23 -O3 tests/ahc004_anchor_congruence_test.cpp -o /tmp/anchor-test
/tmp/anchor-test 768
```

#### 交差盤面を初期解候補にする任意モード

`-DAHC_ANCHOR_GEOMETRY` は、既存初期化を先に終了して最良盤面を保存し、
閉路28本以上・閉路で説明できる読みが重複込み75%以上の場合に限り、
上記の3＋1行を探します。各列マッチングの採用辺について、4行すべて
と一致する実際の位相を取り直してから列を置きます。同じ候補線を重ねず、
続けて既存交点と全て一致する行・列を伸ばします。上位最大4案を通常の
貪欲補完で埋め、厳密な出現数・空白数が既存初期解より改善したときのみ
採用し、残時間は同じ焼きなましに使います。診断用 scout とは単独で指定します。

抽出は12 ms（2.8万訪問）、三行は175 ms（最大136.8万候補）、
第四行は全体開始から940 ms（1,500万候補）、補完の開始は1,000 msを
上限とします。時計は一定間隔で確認するため、開始済みの小処理や補完が
境界を少し越える可能性があります。最終探索の目標は従来どおり2,780 ms。
実測の開始点、補完前後の得点、候補数、上限到達、行列数はstderrに出ます。

幅768の合成検証に、先頭5本に偽線が1本（合計2本のランダムな偽線）
混じる条件を追加しました。24件すべてで作った盤面に選択数以上の
異なるカタログ線を実際に確認しましたが、真の四行相対配置が首位だった
のは30/34/36本の各8件中1/1/3件でした。偽線と未発見線により高得点の
誤配置を選びうるため、公式100件での比較前に既定にはしません。

```bash
/tmp/anchor-test 768 noisy
python3 scripts/bundle.py problems/ahc004/main.cpp -o /tmp/geometry.single.cpp
g++ -std=c++23 -DAHC_ANCHOR_GEOMETRY /tmp/geometry.single.cpp -o /tmp/geometry
```
