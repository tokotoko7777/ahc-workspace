# AHC003

[問題文・公式ローカルテスタ](https://atcoder.jp/contests/ahc003/tasks/ahc003_a)

**比較の目安は未達で、現在の版を保存しています。** 道路の長さと分割位置を、経路に対する応答から逐次推定します。
各線で一定の長さと途中で変化する長さを比較し、分割位置の再推定、各辺の補正、ばらつきの推定を組み合わせています。
`main.cpp` は専用ヘッダを結合済みの、独立に作成した単独のC++17ファイルです。

```sh
g++ -O3 -std=c++17 main.cpp -o solver
./tools/target/release/tester input.txt ./solver
```

公式ツールの展開先に応じて、`tester` のパスを変更してください。
対話型なので、公式の隠し入力ファイルをそのまま `./solver` にリダイレクトして実行する形式ではありません。

同じ実行ファイルで、本番シード先頭30件は平均 **974,119,045.07点**、
未使用の公式生成器seed 20000〜20019は平均 **974,473,661.40点**でした。
合計50件の平均は **974,260,891.60点**、最大時間1.23479秒。
全50件の各1,000応答で、独立した検証と公式テスタの得点が一致しました。

1位の全3,000件平均975,589,247.8123点には、簡易比較でも約133万点届いていません。
1位の同じ50件の得点とは直接比較できておらず、本番順位を確定する結果ではありません。
本番30件は改善にも使用し、追加20件は版と評価計画を固定してから初めて測定しました。

### 使った部品と再現

既存の近似では経路全体の相関を考慮した観測価値を評価できないので、

に疎な観測ベクトルの共分散減少を追加しました。特徴 ID が重複する
経路を、呼び出し側で ID ごとの通過回数に集約します。既存の行優先の
共分散行列をコピーせず渡せます。
[使用例](../../examples/gaussian_linear_information_usage.cpp)、
[密な参照式との 1,000 件の比較](../../tests/gaussian_linear_information_test.cpp)、
[ライブラリ仕様](../../docs/LIBRARY_REFERENCE.md#gaussian-linear-informationhpp)。

C++23 の単一ファイルに結合可能です。以下はリポジトリ直下で実行します。
`gen`、`tester` は、公式配布 Rust アーカイブ中のバイナリの絶対パスです
（`cargo build --release --locked`）。

```bash
bash problems/ahc003/build_experiment.sh build/ahc003
for suite in dev holdout confirm; do
  mkdir -p "build/ahc003/$suite"
  (cd "build/ahc003/$suite" && "$gen" "../../../problems/ahc003/$suite-seeds.txt")
  python3 problems/ahc003/benchmark.py "build/ahc003/$suite/in" \
    "build/ahc003/$suite-results" "$tester" build/ahc003/baseline build/ahc003/probe

```

凍結版で本番を再現するときは、公開本番シードで生成した入力だけを直接
渡し、末尾の `probe` バイナリを省略します。入力とプログラムとテスタの
SHA-256 を保存し、入力・バイナリが変われば既存計測を再使用しません。
公式対話テスタの経路出力を独立採点し、双方の得点が一致したときだけ採用します。

## 経路長の差を狙う観測（追加実験、未採用）

観測候補を `x`、推定最短経路と競合経路の特徴回数の差を `d` とすると、
観測が長さの差の分散を減らす量は `(d^T C x)^2 / (R + x^T C x)` です。
この量を、観測後の推定最短経路が入れ替わる場合の期待改善に変換します。
候補は既存・推定最短・不確実性を強く割り引いた経路の 3 個で、初期 140
クエリの偶数番に限り、予測経路長から期待改善を重み付きで引いて選びます。
期待改善がほぼ 0 なら既存経路を維持します。既定ビルドに変更はありません。

| 独立生成・共通入力 | 既存版 合計 | 経路差版 合計 | 差 | 経路差版勝ち |
|---|---:|---:|---:|---:|
| 新規開発 20 件 | 19,555,825,319 | 19,561,039,366 | +5,214,047 | 12/20 |
| 同一バイナリの新規確認 28 件 | 27,379,000,220 | 27,330,566,566 | −48,433,654 | 9/28 |

全 96 件で公式対話テスタと独立検査が一致。CPU 7 に固定した直列測定で
テスタ込みの最大時間は既存版 0.637 秒未満、経路差版 0.675 秒未満でした。
確認集合で悪化したため、経路差版は本番シードでは評価していません。
確認集合の初期 140 クエリでは両版が異なる経路を返した回数の中央値は
104.5 回です。初期の観測の選び方が、その後の学習経路にも波及します。

トレース用 API は指定した経路対の差の分散を扱えなかったので、
`target_variance_drop` を追加しました。経路に共通する特徴の通過回数は
差を作る際に相殺し、疎な符号付きベクトルを渡します。
[使用例](../../examples/gaussian_linear_information_usage.cpp) と
[密行列での事後分散との差を比較するテスト](../../tests/gaussian_linear_information_test.cpp) も更新しました。

```bash
bash problems/ahc003/run_target_probe.sh build/ahc003-target "$gen" "$tester" 7
```

次の仮説は、現在の出発点・終点の近傍だけでなく、後のクエリで競りやすい
経路対を、過去のクエリから小さな集合として作り、観測の価値を評価することです。
直近の経路が短くなる効果と、将来の経路を選びやすくする効果を分けて測ります。

## 過去に出た別の出発点・終点を使う観測設計（未採用）

初期の候補選択は 16〜226 手目の 6 手ごと（最大 36 回）に限定。
比較候補はその時点の既定経路、推定平均最短、強めに楽観評価した経路。
すでに到着した直近 64 組以内から、最大 8 組の出発点・終点を
参照用に選びます。既存の平均最短路の辺だけを少し高くした探索で
別経路を作り、平均推定の経路長差と通過特徴回数の差を保存します。
参照を更新するのは 3 回の観測候補選択に 1 回です。
未来の出発点・終点や実際の道路長は読みません。

経路候補について `C x` と観測分散を一度だけ計算し、複数の
競合経路差への期待改善を、平均長で正規化して求めます。
対照は同じ候補・参照計算をして、現在の問い合わせの競合経路差
だけを選択判断に使用します。試験版は別の出発点・終点での期待改善も
判断に用います。予測経路長が既定より 2% を超えて悪化する候補、
改善期待が既定より十分増えない候補は除外します。
実時間ガードを置き、実験では両方式とも全ケース 36 回を実行しました。

## 乗法一様ノイズと丸めを使う観測更新（未採用）

真の経路長を `b>0`、整数の観測を `y` とすると、
0.9〜1.1 の一様乗数についての観測確率は
`[min(1.1,(y+0.5)/b)−max(0.9,(y−0.5)/b)]_+ / 0.2` です。
既存のガウス加法誤差を使う変種と比較するため、試験版はこの
厳密な尤度を潜在経路長の正規事前分布に掛けます。
丸め境界で分割した 12 点の Gauss–Legendre 積分で事後平均・分散と
対数尤度を求め、辺の平均・共分散に一次のモーメント更新を行います。
経路候補、選び方、初期探索のスケジュール、区分道路の別フィットは
変えません。推定の変化に応じ、結果として選ぶ経路は変わります。
積分が評価不能なときは元の更新を使います。

| 新規独立シード | 既定の得点 | 丸め尤度版 | 差 | 勝・負 |
|---|---:|---:|---:|---:|
| 開発 20 件 | 19,455,088,205 | 19,477,665,253 | +22,577,048 | 10・10 |
| 凍結後・未調整 32 件 | 31,174,330,843 | 31,198,207,740 | +23,876,897 | 18・14 |
| 同じ版の追加・未調整 24 件 | 23,370,799,143 | 23,363,127,632 | −7,671,511 | 11・13 |

開発・未調整とも 0.0337% 以上かつ半数以上勝ったため、
事前の条件に従って追加 24 件を測りましたが、再現しませんでした。
未調整の二集合を合わせても改善は約 +0.0297% で、必要な幅に
届きません。既定は変更せず、追加の本番評価は実行しませんでした。

全 152 対戦で公式・独立の経路と得点が一致。
CPU 7 固定で候補最大 1.036 秒未満（公式テスタ込み）。
C++23 単一ファイルも試走時の 972,004,937 点・全経路が一致し、
対照の実行ファイルは本番計測の凍結 SHA-256 と一致しました。

[丸め乗法雑音の事後モーメント](../../library/rounded-multiplicative-normal.hpp)
を追加しました。既存の加法ガウス観測の部品だけでは有限支持や丸めの
境界を表せなかったためです。[API と使用例](../../docs/LIBRARY_REFERENCE.md#rounded-multiplicative-normalhpp)、
[乗数方向から独立に積分する 180 件の比較](../../tests/rounded_multiplicative_normal_test.cpp)。
次は効果を分解するため、道路の平均・分散だけをこの積分で更新し、
一定道路と分割道路のモデル選択は従来の評価に固定する対照を試します。

```bash
bash problems/ahc003/run_rounded_likelihood.sh build/ahc003-rounded "$gen" "$tester" 7
```

## 片側に固定しない道路モデルの比較（実験）

既定は、観測尤度が十分に偏るまでは一定道路と分割道路を混合し、
通常は 250 手以降に支持の強い方へ固定します。固定後は片方だけを
学習し、計算量を抑えます。固定前の「期待加法差」を最小化する
だけなら、既定の平均辺コストと本質的に同じです。

試験版は固定条件に達するまでは既定と同じです。その後も両方の
予測尤度を比較し、優勢な一方だけを毎手更新することで、更新回数を
揃えながら学習対象を切り替えられるようにします。
更新を止めた側は疎な経路特徴だけで対数尤度を計算し、
密な共分散行列は更新しません。対数尤度の係数・閾値は既存と同じ。
経路選択では、公式の `1−a/b` 型の相対損失の一次近似として、
各モデルの二つの L 字経路のうち短いものを長さの目安に、
事後確率をその長さで割って重み付けします。
最短経路探索は双方とも毎手 1 回です。

```bash
bash problems/ahc003/run_reversible_ensemble.sh build/ahc003-ensemble "$gen" "$tester" 7
```

開発 20 件の両方式は **19,550,534,064 点**、未調整 32 件も
両方式 **31,213,793,959 点**。52 件すべて、全 1,000 経路が
バイト単位で一致しました。固定条件の後に行った両尤度の照合は
開発 14,726 回、未調整 23,288 回で、優勢側の入れ替わりはどちらも
ゼロでした。相対損失用の重みを含めても、事後確率の偏り
`|2p−1|` の平均はそれぞれ 0.9999915、0.9999945。
このモデルでは固定が実際に問題になる兆候を確認できませんでした。

既定は変えず、`-DAHC_REVERSIBLE_ENSEMBLE` で再現できます。
事前の 0.0337% 改善条件を満たさず、追加確認・本番試験は行わず終了。
全 104 対戦の公式・独立結果が一致し、候補の最大壁時間は
CPU 7 固定・テスタ込み 0.885 秒未満。
C++23 単一ファイルの試走も 976,252,282 点・全経路一致でした。
疎な尤度評価と元の更新が返す尤度が同一であることは合成 500 件で確認しました。
今後はモデル選択の可逆化より、優勢モデル内部の道路分割や
残差の表現を見直す方が、経路が実際に変わる仮説になります。
