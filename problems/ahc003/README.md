# AHC003

[問題文・公式ローカルテスタ](https://atcoder.jp/contests/ahc003/tasks/ahc003_a)

**比較の目安は未達で、現在の版を保存しています。** 道路の長さと分割位置を、経路に対する応答から逐次推定します。
各線で一定の長さと途中で変化する長さを比較し、分割位置の再推定、各辺の補正、ばらつきの推定を組み合わせています。
`main.cpp` は専用ヘッダを結合済みの、独立に作成した単独のC++17ファイルです。

```sh
g++ -O3 -std=c++17 main.cpp -o solver
./tools/target/release/tester input.txt ./solver
```

公式ツールの展開先に応じて、`tester` のパスを変更してください。
対話型なので、公式の隠し入力ファイルをそのまま `./solver` にリダイレクトして実行する形式ではありません。

同じ実行ファイルで、本番シード先頭30件は平均 **974,119,045.07点**、
未使用の公式生成器seed 20000〜20019は平均 **974,473,661.40点**でした。
合計50件の平均は **974,260,891.60点**、最大時間1.23479秒。
全50件の各1,000応答で、独立した検証と公式テスタの得点が一致しました。

1位の全3,000件平均975,589,247.8123点には、簡易比較でも約133万点届いていません。
1位の同じ50件の得点とは直接比較できておらず、本番順位を確定する結果ではありません。
本番30件は改善にも使用し、追加20件は版と評価計画を固定してから初めて測定しました。

## 経路全体の情報量による初期探索（実験、未採用）

既存版の各辺の不確実性を使った経路に加え、推定値だけを使う候補と、
不確実性を強く差し引く候補を生成します。初期 140 クエリの偶数番だけ、
各経路を実際に観測した場合にモデル全体の事後分散がどれだけ減るかを
予測し、予測経路長と比べます。探索の強さはこの範囲で線形に下げます。
経路の推定分散には特徴の相関と経路長に応じた観測雑音を反映しました。
既定のビルドは変更していません。

| 独立生成・共通入力 | 既存版 合計 | 情報量版 合計 | 差 | 情報量版勝ち |
|---|---:|---:|---:|---:|
| 新規開発 16 件 | 15,596,605,453 | 15,585,771,777 | −10,833,676 | 4/16 |
| 事前凍結の未調整 24 件 | 23,338,874,217 | 23,389,938,177 | +51,063,960 | 15/24 |
| バイナリを変えず追加確認 24 件 | 23,462,169,912 | 23,440,620,754 | −21,549,158 | 13/24 |

両版の 128 件すべてで公式対話テスタと独立した経路・得点検査が一致しました。
最大実測は既存 0.624 秒未満、情報量版 0.692 秒未満（Linux、CPU 7 に固定、
直列、対話テスタ込み）。未調整集合では伸びましたが、追加確認で合計改善を
再現できず、不採用としました。この結果から本番順位は判定しません。

### 採点の出典と本番比較

[公式問題](https://atcoder.jp/contests/ahc003/tasks/ahc003_a)の得点は
各ケースで `round(2312311 * sum(0.998^(1000-k) * a_k/b_k))`
を計算し、本番 3,000 件の合計を最大化します。初期・終点、重複頂点、
盤外を検査し、本番では非 AC のケースだけ 0 点です。実行制限は
2 秒・1,024 MiB です。本番シードは
[公開ファイル](https://img.atcoder.jp/ahc003/seeds.txt)の MD5
`0cf5051d586e7f62c0b3527f6f7fbb1c` と照合しました。
[AtCoder 提供の順位アーカイブ](https://huggingface.co/datasets/SakanaAI/ALE-Bench/blob/main/ahc003.zip)
の `standings_scores.csv` にある最終 1 位の合計は
**2,926,767,743,437 点**（配布ファイル SHA-256
`92a5713798684a4e334a7d1b0782a3ebc613ab6bb85372f76d60fb8ca7345fcb`）。
得点集計の先頭順位だけを確認しました。

同じ実行形式で採用候補を検証するため、ローカル比較を終えてから既存版を
凍結し、公開本番 3,000 件を公式ジェネレータとテスタで評価しています。
本番を調整には使いません。比較結果は AtCoder に再提出したものではなく、
自前の実行機上で本番入力と採点を再現したものです。

### 使った部品と再現

既存の近似では経路全体の相関を考慮した観測価値を評価できないので、
[gaussian-linear-information.hpp](../../library/gaussian-linear-information.hpp)
に疎な観測ベクトルの共分散減少を追加しました。特徴 ID が重複する
経路を、呼び出し側で ID ごとの通過回数に集約します。既存の行優先の
共分散行列をコピーせず渡せます。
[使用例](../../examples/gaussian_linear_information_usage.cpp)、
[密な参照式との 1,000 件の比較](../../tests/gaussian_linear_information_test.cpp)、
[ライブラリ仕様](../../docs/LIBRARY_REFERENCE.md#gaussian-linear-informationhpp)。

C++23 の単一ファイルに結合可能です。以下はリポジトリ直下で実行します。
`gen`、`tester` は、公式配布 Rust アーカイブ中のバイナリの絶対パスです
（`cargo build --release --locked`）。

```bash
bash problems/ahc003/build_experiment.sh build/ahc003
for suite in dev holdout confirm; do
  mkdir -p "build/ahc003/$suite"
  (cd "build/ahc003/$suite" && "$gen" "../../../problems/ahc003/$suite-seeds.txt")
  python3 problems/ahc003/benchmark.py "build/ahc003/$suite/in" \
    "build/ahc003/$suite-results" "$tester" build/ahc003/baseline build/ahc003/probe
done
```

凍結版で本番を再現するときは、公開本番シードで生成した入力だけを直接
渡し、末尾の `probe` バイナリを省略します。入力とプログラムとテスタの
SHA-256 を保存し、入力・バイナリが変われば既存計測を再使用しません。
公式対話テスタの経路出力を独立採点し、双方の得点が一致したときだけ採用します。

次はモデル全体のトレースを減らすのではなく、競合する近い経路どうしの
「長さの差」の推定分散を選択的に減らす観測を検討します。
