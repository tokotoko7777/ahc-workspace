# AHC019

[公式問題・採点規則](https://atcoder.jp/contests/ahc019/tasks/ahc019_a) /
[公式 Rust ツール](https://img.atcoder.jp/ahc019/b36525d8.zip)。
2 組のシルエットのそれぞれを、同じポリキューブのセットで再現します。

## Ａ/Ｂ

基準版は z 断面ごとに、正面・右から見える未充足の位置を組み合わせ、
最小個数の単位立方体で投影を埋めます。両方の単位立方体に共通番号を
付け、個数の差だけ片方専用です。

共通ブロック版は、各立体で許される空きマスを一つずつ選んで重ね、
24 種類の正回転の一つで方向を対応させます。その状態から、両側に
移せる面隣接セルを同時にたどって連結ブロックを作ります。新しく
埋まる投影を計算し、残りの投影を単位立方体で補う必要個数が減る
候補を優先します。複数の初期探索を試し、残りを同じ基準処理で埋め、
絶対評価が最良の合法解を返します。入力番号や公開本番入力には
依存しません。

| 共通乱数入力（D=5〜14 均等） | 単位立方体のみ | 共通ブロック版 | 共通ブロック版勝ち |
|---|---:|---:|---:|
| 開発 10 件 | 529,000,000,000 | 10,885,395,414 | 10/10 |
| 凍結後・未調整 20 件 | 1,071,000,000,000 | 38,523,747,247 | 20/20 |

絶対評価は小さい方が良く、未調整集合では 96.4% 減少しました。
片方しか使わない体積の合計は未調整集合で 64→6。今回の最大共通
ブロックは開発集合の 411 立方体でした。投影・面連結・共通形状を
独立検証し、全 60 実行で公式 `vis` の整数評価と一致しました。
CPU 7 固定の実測最大壁時間は 0.056 秒未満（採点を除く）。
基準版を含めて選ぶ共通ブロック版を作業ブランチ既定にしました。

## 本番順位との比較

未使用の総体積を `r1+r2`、両方で使うブロックの体積を `v` とすると、
絶対評価は `round(10^9 × (r1+r2+Σ 1/v))`、小さい方が良いです。
本番は `round(10^9 × そのケースの全参加者の最小評価 / 自分の評価)`
を D=5〜14 の各 200 件、計 2,000 件で合計し、大きい方が上位です。
非 AC はそのケースだけ 0 点で基準値からも除外されます。
制限時間は 6 秒、メモリは 1,024 MiB。

本番 1 位の相対点は **1,886,240,066,109 点**。
[AtCoder 提供の ALE-Bench アーカイブ](https://huggingface.co/datasets/SakanaAI/ALE-Bench/blob/main/ahc019.zip)
を SHA-256 `0d6fcdb3d26939918d3a5b49a81ced6e042b8351e667121e51396a00fd60efe8`
で照合し、順位・得点 CSV のみ確認しました。
[公式本番シード 2,000 件](https://img.atcoder.jp/ahc019/seeds.txt) の
SHA-256 `08db725cbdc37734a2e8fbe5bc0cbc1e95d7a68933b7f43dcdd0ffc3d2a95e34`
は公式問題文と一致しました。今回の A/B のシードとは重複しません。
公式ケース別の基準値（全参加者の最小評価）は未取得で、本番ケースは
生成・評価していません。**厳密な本番順位は未判定**です。

## 再現とライブラリ

公式配布 zip SHA-256:
`2978a1bbb6a4ec2c28f4819007af65bdc9b923730d537d0e7f388a6c4282e71d`。
`cargo build --release --locked --bin gen --bin vis` で公式ツールを
ビルドし、その絶対パスを指定します。開発・確認のケースは、公式
ジェネレータに D を明示してサイズが均等になるよう生成します。

```bash
bash problems/ahc019/run.sh build/ahc019 "$gen" "$vis" 7
```

C++23 提出用の単一ファイルも生成・ビルドします。D=14 の未調整ケース
1 件で、通常ビルドと単一ファイルの得点 1,744,288,308 が一致しました。
凍結した共通ブロック版 SHA-256:
`cd3cac17f03a2d8fb6aa7a63c67c5384c8ec34501aa042f285fdc29052696777`。

既存の 2 次元の点・回転部品では 3 次元の軸方向の対応を表現できないため、
[`cube-rotations.hpp`](../../library/cube-rotations.hpp) を追加しました。
[使用例](../../examples/cube_rotations_usage.cpp)、
[行列式・閉包性と鏡像の検査](../../tests/cube_rotations_test.cpp)、
[API](../../docs/LIBRARY_REFERENCE.md#cube-rotations)。既存提出や外部解説は
使っていません。

次は、末尾に専用の立方体が残る原因を減らすため、先に置いた共有
ブロックを平行移動・縮小して、後続に別の回転を当てられる領域を
空けます。各側に余った投影の補完数を見て、2〜3 個のブロックをまとめて
作り直す近傍を、同じ時間での再始動増加と比較します。
