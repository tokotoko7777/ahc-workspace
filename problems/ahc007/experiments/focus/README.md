# AHC007 集中研究の追試
この場所の仮説は公式解説や他人の提出コードを見ず、公式問題・入力生成規則と
このリポジトリの既存実装から立てた。配布・開発・未使用・本番を混同しない。
採点は一辺ずつ渡す GNU C++23 solver と公式 vis、および整数丸めの独立採点を照合する。

## 結果として残す研究枝
- [凍結した上位3辺の逐次期待費用DP](../pivotal_online): 公式配布150件
  **14,253,784,455**、未使用150件 **14,233,087,895**。
- [順位ビット集合なしでも速い双方向探索＋補正](../adaptive_risk): 公式配布150件
  **14,247,857,888**。
- [直列と並列で補正を分ける符号付き版](../signed_witness_risk): 公式配布150件
  **14,255,819,331**、別の未調整150件 **14,249,050,741**。
- 数値目標は **14,241,733,941**。配布で上回っただけでは本番順位を主張しない。
  同一セットを使う確認には、AtCoder提供 ALE-Bench full の blind replay を用いる。

## 試して分かったこと
- 既存の24標本版は配布150件 **14,184,305,386**。150件公式採点同一。
  真の長さを知る未来のボトルネックを推定するため、同じ期待費用でも
  将来の採否の自由度を過大評価・過小評価することがあった。
- **枝刈りの固定仕事量:** 層化96標本＋適応早期終了の同一の開発24入力。
  過去辺を毎回読む既存順序走査と、順位を消す版は 707,168標本・
  全24採否列で一致。最大 solver CPU **0.525秒 → 0.259秒**、最大
  lock-step wall **0.545秒 → 0.274秒**。標本を常に24のみ使う版では初期化が
  割高になり、別途測った最大CPUが0.186→0.259秒。万能置換ではない。
- **候補準備の別案:** 128ターンごとの接尾MSF証明書は厳密だが、同一24標本では
  組み立てコストで増速しなかった。双方向探索も同一24標本の初期4件では
  既存より遅い一方、拮抗だけ深く調べる符号付き方策では高得点・短時間。
- **標本の作り方:** 反対側の一様標本をペアにする、全接頭辞を二進層化する、
  未来の採否閾値を超えた標本辺を重くする方法は、試した開発集合で
  最良を更新しなかった。並行実行で時間が歪んだ初期結果は速度評価から除外。
- **逐次DP:** 3本だけ真値を未公開にした差を足すと開発24件で
  +5,312,546（同じ64標本方式）。5〜7本に増やす、補正のための標本を増やす、
  条件付き全知の期待値でベースをブレンドする改善は、増やすほど良い傾向なし。
  実グラフの小さな二重連結成分を厳密に解く方法は、同一比較で
  24件合計+163,045、変更わずか8判断。採用保留。
- 符号付き補正は、サンプルで経路のボトルネックに選ばれた辺の真値が
  幾何期待値より低いか高いかを見て、並列的な取り逃しと直列的な
  早買いを区別する。固定長の再生より少ない時間で補正できる。

## 実験再開用
公式 gen で公開開発 seed 27,000,400〜27,000,549 を生成し、先頭24件を短期比較。
未使用は 27,000,550〜27,000,699。これらは本番とは別。非公開の値は出力しない。
```sh
g++ -std=c++23 -DAHC_ACTIVE_SAMPLES -DAHC_ADAPTIVE=265 -DAHC_SAMPLE_COUNT=128 \
    -DAHC_STRATIFIED -DAHC_PIVOTAL=3 -DAHC_RISK=30 problems/ahc007/main.cpp -o pivotal
python3 problems/ahc007/benchmark.py "$INPUTS" paired "$VIS" old pivotal
```
研究用エントリの `AHC_PIVOTAL` は未公開で評価する上位辺の件数、
`AHC_SMALLBLOCK` は小ブロックの最大頂点数。再現の正式な保存源は個別の
凍結した単一ファイルを使う。次は実験で見つかった符号・候補数の効果を、
別分布でも確認し、特定の入力に合わせたルールを避ける。
