# AHC007: 上位の代替辺を未公開のまま評価
[公式問題・採点規則](https://atcoder.jp/contests/ahc007/tasks/ahc007_a) /
[公式ツールと配布150ケース](https://img.atcoder.jp/ahc007/a855b6a456c9892b747e147001b0f89.zip)。
公式問題の同梱150ケース（seed 0–149）で **14,253,784,455**。旧版
14,184,305,386比 +69,479,069、150件中120勝、公式 vis と独立採点は
全件一致。最長0.441秒、solver CPU 0.426秒未満。これは本番1位の数値
14,241,733,941を +12,050,514 上回るが、配布ケースと本番の順位比較とは別。
未調整150件（公式 gen seed 27,000,550–27,000,699）では本単一ファイルで
14,233,087,895、独立に作った risk-only 版に +11,647,150（86勝）、
最長0.443秒。未調整セットでも150件すべて両採点一致。研究継続中。

採択済みの辺を縮約し、現在の端点を既に結べる場合は棄却。未来だけでは
接続不能なら必ず採択。それ以外は、未来の重みの標本から代替路の
ボトルネックを推定する。辺番号と縮約で無効になった候補を順位ビット集合
から消し、Kruskal の仕事を減らす。判断が拮抗するときだけ標本を追加する。

さらに、標本のボトルネックに出やすい辺を3本選び、その長さを未公開の
まま残す。他の辺の重みを標本内で固定して、3本の採否時点に即した期待
コストを部分集合DPで計算する。固定した残りは、端点間の接続閾値を保つ
小さな森に圧縮する。同条件で未来を全部知る場合との差を元の閾値に足し、
選べなかった代替辺の不確かさは残りの分散で補う。

公式ツールのビルド: `cargo build --release --locked --bin vis`。
リポジトリのルートから、単一ファイルを追加最適化フラグなしでビルド:
```sh
g++ -std=c++23 problems/ahc007/experiments/pivotal_online/submission.single.cpp -o ahc007
python3 problems/ahc007/benchmark.py "$PUBLIC_INPUTS" result "$VIS" ahc007 ahc007
```
入力すべてを先に読まないことを、辺を1本ずつ渡す逐次入出力で確認する。
