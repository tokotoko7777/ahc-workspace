## 何に使うか

事前に決めた作業順について、
「途中でどの柵にも干渉せず、予定の時刻に指定位置にいる」
という**同時確率**を計算する。各時刻の確率の積とは異なる。
静的な盤面で時間内に一度でも到達する問題には従来の
`CaptureWindow`を使う。こちらは途中で通行可能な頂点が減り、
条件を各作業直前と最後に満たすかを判定する。

1. 各フェーズで、`forbidden_before` と `close` にいる確率質量を捨てる。
2. `close` を通行不能にし、その盤面で `steps_after` 回歩く。
3. 全フェーズ後の許容地点の質量を合計する。失敗分は**正規化しない**。

頂点は0始まり、隣接先は整数の範囲。通れる隣接先を等確率で選ぶ。
同じ隣接先を複数回渡せばその回数分の重み。行き先がなければ停止する。
閉鎖できるかが隣接マスにも依存するなら、そのマスを明示的に
`forbidden_before` に渡す。閉鎖位置自体は自動で禁止される。
最後の人の操作直後に観測するなら、最終フェーズの歩数は0。
`WalkScheduleWorkspace` は問い合わせ間でメモリを再利用する。
グラフとフェーズが固定の計算。対象の反応で作業を取り消す
オンライン方針や、目標へ向かう動物の確率は扱わない。
独立な歩行者かつ固定日程のときだけ、個体別の値を掛けられる。

## 検証とAHC008での利用

- 有向グラフを含む4,000個の小例で、あり得る経路を全列挙して照合。
  `g++ -std=gnu++23 -Wall -Wextra -Werror tests/fixed_walk_schedule_test.cpp -o test && ./test`
- [進捗記録](../AHC_PROGRESS.md)の中盤、捕獲に先立つ入口を含む
  4〜6手の固定日程37候補で、Python版と絶対誤差 `1e-12` 以内。
  受動型の柵への干渉と、受動型が対象の場合の到達をまとめて計算した。
  犬・猫を除いた値なので、全体確率の上界であり、犬・猫の到来率ではない。
  実物由来の各37候補を3回ずつ計算し、条件を揃えて8組を交互に測ると、
  中央値はPython版86.84ms、C++呼び出しと変換込み34.79ms。
  **確率計算の比較**で、ソルバーの実行時間や得点改善ではない。
