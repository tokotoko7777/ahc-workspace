# 最大流と最小カットで残余 BFS を共有する

[ヘッダー](../../library/max-flow.hpp) /
[短い例](../../examples/flow_and_min_cut_usage.cpp) /
[全列挙との照合](../../tests/flow_and_min_cut_test.cpp)

流量と最小カットの両方が必要なら、連続した `flow(s,t)` と
`min_cut(s)` の代わりに `auto [value, source_side] =
g.flow_and_min_cut(s,t);` を使える。返る流量は呼び出し時点の残余
グラフから追加できた量、`source_side[v]` は終了時に s から到達
できるかどうか。s 側が包含最小のカットを返す。

Dinic の最後の層探索は t に届かなかったため、残余グラフの s
側全体をすでに訪問している。追加の探索をせず、その訪問印を
返す。整数型の上限まで流れた場合は終了の証明に限りもう一度
探索し、まだ t に届くなら `std::overflow_error`。整数型で使い、
既存の `flow` と `min_cut` は変更しない。

9頂点未満の乱択グラフ1万件で、すべてのカットの列挙、包含最小
の s 側、既存 API の戻り値、途中まで流した状態からの再開と照合。
整数上限ぴったりの場合と、上限を超える場合を個別に検証。

AHC008では終盤の追い込みで、人の側と動物の側を分ける柵を
求めるときに利用。公式配布100件の固定24波で、全ての行動と
得点・探索回数が同じ。探索が動いた16件の実行時間短縮は中央値
約29.2ms。同じ2,400ms上限では 1,286→1,315 波、得点は
6,202,333,331点で変化なし。速度は盤面、容量、探索中の状態に
依存する。

成功する層探索も、t を最初に発見したところで止められる。
探索は BFS 順なので、その時点で t の直前の層にある頂点の
レベルはすべて確定している。最短増加路を取りこぼさない。
到達に失敗する探索は最後まで走り、s 側の取得に使う。
`flow_and_min_cut(s,t,false)` はこの途中打ち切りをしない。
従来の `flow`・`min_cut` の動作は従来どおり。

終盤の比較は引き続き配布100件。最後の BFS の再利用を有効に
した版から、成功時の打ち切りも加えると、固定の24波で全操作、
得点、探索数が一致したまま、探索が動いた16件の所要時間合計は
14.578→13.709秒。同じ2,400ms上限では1,312→1,406波（+7.2%）、
全100件の操作・得点は変化なし。経過時間は同時並列実行せず測定。
