# 頂点分割の最小カットで、既に通れないマスを除く

## 使う場面

グリッドの各マスを入口・出口に分割し、入口→出口の容量を使って「このマスを塞ぐ費用」を表す。地形として既に閉じているマスや盤外の内部辺は常に容量0。これらを通常のグリッドと同じようにネットワークへ入れると、流れを運べない辺の追加・走査・確保が毎回発生する。

## 置き換え

- 閉じたマスの内部辺と、そのマスに接する隣接辺を省略する。
- 始点から当該マスの入口へしか行けず、出口へ進めない辺は省略できる。ただし辺数や重みが目的関数の別の定数を決めている場合は、その数値計算は維持する。
- 元の辺番号を必要とする用途ではマスの番号を維持し、無操作の頂点として残してよい。未閉鎖マスでの辺順序を変えないと、もとの実装との比較が容易。
- 入口や出口に別の接続があり「内部辺を迂回できる」ネットワークでは、この省略は一般には正しくない。

容量0の内部辺は正の流れを流せない。入辺は入口、出辺は出口に分離されており、元のネットワークの任意の正の増加路は閉じたマスを通らない。したがって残る開放頂点での最大流値・カット判定を保つ。除去したマス自身の残余到達性は比較しない。

## AHC008での検証

- 本番想定の処理系では、独立ランダム560盤面で最小カットのマス、最大流値、人側の判定、目的関数定数が一致。
- 公式配布100件で、1件の比較シミュレーションを最大24組に固定すると、全行動・全得点・実行した408組が一致。終盤探索が走った同じ17件のCPU時間合計は22.16→17.61秒（約20.5%減）。
- 通常時間枠では終盤の比較が1,036→1,328組に増えた。全頭捕獲・全員が同じ空間は両版100件だが、1件で作戦切替の判断が変わって10マス失ったため、単体では得点最良版に未採用。近似シミュレーションを増やすほど実得点も改善するとは限らない。
