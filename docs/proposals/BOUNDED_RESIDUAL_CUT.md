# 追加コストに上限を置いた最小カットの再探索

[ヘッダー](../../library/bounded-residual-cut.hpp) /
[短い例](../../examples/bounded_residual_cut_usage.cpp) /
[全列挙との照合](../../tests/bounded_residual_cut_test.cpp)

最大流を最後まで解いたネットワークを受け取り、最小カットの始点側に
条件を追加する。その条件を満たすカットが、元の最小値より高々 B だけ
高いかを調べる。1条件は `u が始点側なら v も始点側` の有向辺。
頂点を始点側に固定するには `(s,u)`、終点側なら `(u,t)`。
頂点分割で柵を表すなら、2ノードを同じ側に置くような条件を加えられる。
返り値には実際の追加量と最小の始点側、必要なら最大の始点側が入る。

元のカット容量は、元の最大流 F と、その残余グラフで同じ分割から
外へ出る容量の和。残余をコピーし、条件辺を容量 B+1 で足して、
流量 B+1 で打ち切ればよい。B+1 に到達したら予算内の解はない。
元のグラフは変更しない。残余が未解決のグラフは渡さない。
容量は非負整数、B+1 が容量型に収まる必要がある。

AHC008では複数の柵が同じ担当に集中する候補で、未配置の柵の
うちいくつかを切らずにすむ代案を探した。「同じ動物を隔離し、
同じ程度の共有地が残るか」「ひとり一枚で到着が間に合うか」は
別の制約として確認する。モデル上の追加コストを得点と解釈しない。
配布100件のうち終盤に追い込みを選んだ13件で、問題側の直接計算と
汎用ヘッダー適用後の検査出力・操作・得点は一致した。
3,500小グラフ・24,500条件で可能性、追加量、両端の解を全列挙と照合。

## 小さな予算で同じ残余へ何度も照会する

[`TinyBudgetWorkspace`](../../library/tiny-budget-residual-cut.hpp) は最初に
残余グラフを連続配列に並べ、照会ごとに連続した容量だけをコピーする。
増分流をB+1単位までしか流さないので、小さい整数予算向け。
元のグラフは触らない。1回だけ、または大きな予算では上の通常版を使う。

[連続照会の例](../../examples/tiny_budget_residual_cut_usage.cpp) /
[全列挙・通常版との照合](../../tests/tiny_budget_residual_cut_test.cpp) /
[30×30格子の計測コード](../../examples/tiny_budget_residual_cut_bench.cpp)。
同じ24,500条件で通常版・全列挙と一致。AHC008の13件の検査対象でも、
配列版に替えて条件別の出力がバイト一致した。合成格子で180回×8組を
同一条件で測ると、中央値は約28.7ms→2.5ms（準備を含む）。
この値は切り直し照会だけの測定で、ソルバー全体の高速化ではない。
