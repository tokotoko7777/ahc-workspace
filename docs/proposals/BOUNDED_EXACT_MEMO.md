# 固定容量・完全一致メモの提案

高価な決定処理を繰り返すとき、結果に影響する入力だけをキーにできる場合に使う。ハッシュ値は格納先を選ぶだけで、再利用する前にキー本体の等価性を確認する。同じ場所に異なるキーが来ると上書きする。容量は2の冪。ポインタは同じスロットの上書き、または `clear()` で無効になる。検索中の再帰アクセスや並行アクセスは想定しない。

```cpp
#include "library/bounded-exact-memo.hpp"
#include <array>

ahc::BoundedExactMemo<std::array<int, 2>, int, 64> memo;
std::array<int, 2> key{7, 3};
const auto hash = 131ULL * key[0] + key[1];
const auto [value, hit] = memo.get_or_compute(key, hash, [&] {
    return key[0] * key[1]; // ここを高価な決定処理に置き換える
});
```

## 実問題での使い所

AHC008の終盤の仮想追い込み。盤面の柵・順序付きの人の位置・その人たちから到達できる動物の位置をキーにし、次の1手と対象が空かどうかを保存する。配置、人数、動物数、方針の段階、採用した固定コンテキストを動かす場合はメモを破棄する。人が分断されている場合は動物位置を一つも省略しない。

位置を省けることは問題固有の条件で、キャッシュ部品が保証するものではない。固定仕事量では公式配布100件・各例最大24組で、個別の操作列・得点・仮想得点合計が完全一致。元の完全状態キーは7/2,893命中に対し、不要な位置を省く案は933/2,893命中。933件すべてをキャッシュを使わず再計算した別ビルドでも次の手と停止条件が一致した。

専用版の通常時間枠では配布100件で1,028→1,414組、別の公式生成100件で1,069→1,433組を完走した。ただし比較数が増えると方針の選択も変わり、配布100件は6,191,777,779→6,190,666,668点、別の100件は6,087,214,286→6,115,992,064点。**同じ入力を同じ回数だけ計算した場合の厳密性と、時間制限下で選ばれた結果の良し悪しを分けて扱う。** 既定解は据え置き。

```bash
g++ -std=gnu++23 -O2 -Wall -Wextra -pedantic-errors -I library \
  tests/bounded-exact-memo-test.cpp -o /tmp/bounded_exact_memo_test
/tmp/bounded_exact_memo_test
```

12,000回の乱択検査で、衝突、追い出し、同値キー、固定コンテキスト変更時の初期化、計算の回数を照合する。一般化したヘッダーは専用のスロット管理だけを置き換え、AHC008固有のキー生成や到達判定を含めない。
