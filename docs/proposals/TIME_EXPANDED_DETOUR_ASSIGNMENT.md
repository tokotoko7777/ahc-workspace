# 柵の時刻を保ったまま担当を迂回・復帰させる

複数の人が「最短距離では間に合う」ことと、別々の担当が元の仕事を残して全員戻れることは異なる。時間展開グラフと二部マッチングで、短い区間だけ担当を変更する案を検査する。

## 前提と手順

- 出発時刻、追加の柵を置く時刻、復帰時刻を固定。残す柵の位置・置くターン・担当者も固定する。
- 各担当について復帰地点から時間を逆にたどる。状態は `(時刻, マス)`。通常は上下左右と待機を逆遷移にし、元の柵の設置があるターンは隣接位置で足を止める設置遷移だけを許す。そのターンに塞がれるマスに立つ・入る遷移は禁止。
- 追加の柵への各担当の候補について、指定ターンに隣接して設置できることを逆探索に追加。予定済みで同じ柵が置かれるなら二重に割り当てない。
- 担当と追加の柵を二部マッチング。追加の仕事をしない人にも、柵の変更後に元の仕事を行って復帰できる「追加担当なし」の枠を設ける。必要な全枠を存在確認してからコマンド列を復元する。
- この判定が正確なのは、同一マスへの複数人の滞在が許され、干渉が既知の柵設置に限られるモデル。占有衝突がある問題では別の検査が必要。対象の移動が担当に反応するなら、実際の環境でリプレイする。

## 検証と適用

- 小さな合成盤面600組を全担当の行動列の全列挙と照合。各入口に少なくとも1人ずつ候補がいる357組でも、うち179組は同時割当不可だった。これは合成テストであり、AHC008の発生率ではない。
- AHC008のコンパクト捕獲候補では、本来の柵を残して復帰できた1案が実際に2口を閉じ、3マスに1頭を捕獲した。しかしその後の動物の軌跡が変わり、最終の全頭捕獲には失敗した。経路の可否と捕獲戦略の採否を分ける用途向け。
- 実装候補：既存BFS・マッチングの上に小さい区間専用ヘルパー。日常探索ではベタな時空間グラフ確保を避け、到達セルの疎なリスト、同じ時刻の障害マスク共有、復元は選ばれた割当だけにする。
