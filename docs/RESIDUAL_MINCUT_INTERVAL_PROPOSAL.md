# MaxFlow: 最小カットのうち、始点側が最大になるものを取得する

## 欲しかったこと

AHC008 の終盤は、壁を置く箇所を頂点分割した最大流で求める。最小カットが複数ある場合、既存の `min_cut(source)` は始点側が最小のものを返す。同じ主評価・同じ捕獲対象でも広い側を動物に割り当てることがある。カット容量を変えずに始点側を広げたい。柵の置き方と動物・作業者の固定条件は問題側で決め、汎用部品は残余グラフだけを扱う。

## 提案 API

```cpp
// 完全な最大流の計算後。curr flow / residual graph は書き換えない。
std::vector<char> maximal_min_cut(
    int sink, std::span<const int> additionally_fixed_sink_side = {}) const;
```

各頂点から sink や固定頂点へ正容量の残余路で到達できるかを、逆向き探索1回で調べる。その補集合が始点側。逆向き探索では、頂点 v の隣接要素 e ごとに、その相方 `graph[e.to][e.reverse_index]` の残余容量を検査する。クラスは対になる残余辺を持つため、逆辺リストや補助 max-flow は不要。時間 O(V+E)、追加メモリ O(V)。

使用例: 最大流を最後まで実行し、`min_cut(s)` を一度得る。最小の始点側で sink 側にある頂点だけを追加固定にすれば、元の最小カットが適合するので矛盾は起きない。別の条件で固定する場合は結果に s が含まれることを確認する。含まれなければ、指定した固定条件で元と同じ容量の最小カットはない。流量制限で途中停止した残余状態には「最小カット」の保証はない。

## 正しさ

最大流後、ある s–t カットの容量が最大流値に等しいための必要十分条件は、その始点側から外へ出る正容量の残余辺がないこと。従って t や固定頂点に残余路で到達する頂点を始点側に含めてはならない。到達できる頂点を全部除いた集合は正容量の残余辺について前向き閉集合になる。s を含む限り最小カットであり、他の適合カットの始点側をすべて含む。固定なしなら従来の `min_cut(s)` と対になり、両者の差集合がタイによってどちら側にも動く候補。

## 検証方法

試作は小さいランダム有向グラフ1,600件で全 s–t 分割を列挙し、最小容量かつ固定条件を満たす始点集合の総和集合との一致を確認した。並行辺・逆向き辺・自己ループ・ゼロ容量・孤立頂点も含める。「始点側頂点集合が広がる」は定理だが、問題側で実際に壁を置いた後の捕獲・行動や連結面積までは保証しない。
