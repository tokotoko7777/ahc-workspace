# 固定グリッドの通行先を順序付きで再利用する提案

- 想定: ロールアウトや予測試行で、小さな格子の同じ壁集合を何度も読む。1セルずつ近傍を生成して壁を判定する代わりに、セルごとの「通れる隣」を小さな固定長配列と個数で保持する。
- 最小API案: `StaticGridSteps<Rows, Cols, Degree>::rebuild(wall_mask, directions)` と `open_neighbors(cell)`。上下左右なら最大4。隣接順は指定を保持する。遷移先の壁だけを除くか、出発セルの壁も除くかを明文化し、仮壁の上から退避を許す用法は明示する。
- 更新: 壁が変わったら作り直す。最初は差分更新や全状態キャッシュを導入しない。試行対象がなければ構築しない。小さな盤面で多く再利用するときに絞って実測する。
- テスト: 全セルの順序付き近傍を愚直な列挙と比較。盤端・孤立・到達不能／退避の端条件を確認。固定seedの予測なら分布だけでなく終了時の乱数状態と行動も一致させ、乱数消費順による見かけの差を避ける。
- AHC008: 同じ予定柵の上で30ターン×100試行を繰り返す捕獲予測で使用。128のランダム盤面の集計と最終乱数状態、同じ作業量の配布100と別seed100の全行動・得点が一致。先行の配員高速版からCPU合計をそれぞれ13.06%、12.17%削減した。他問題への外挿や得点更新ではない。
- 対応状況: 問題内の実装と汎用化提案のみ。共通ライブラリは変更していない。
