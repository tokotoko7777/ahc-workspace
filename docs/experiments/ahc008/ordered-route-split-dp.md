# 連続区間を分担する部分集合DPの高速化提案

順序付きの仕事を、各担当者に空でない一つの連続区間として割り当てる。
担当者順と区間内の向きは自由で、全員の終了時刻の最大値を最小化する。
AHC008の設営ではこの初期DPが、終盤試行のないケースの測定対象時間の
55.3%を占めていた。候補は[実装・再現結果](https://github.com/tokotoko7777/ahc-workspace/blob/54cf9c1764a4fc02f876106f2ce8f679fc553b39/problems/ahc008/experiments/20261122/article-capture/terry-split-dp/RESULT.md)の `split.hpp`。

- 仕事数をL、済んだ仕事の前方長をp、残り人数をr、1人の区間長上限をWと
  すると、L−p が [r, rW] にない状態は最終解に到達しない。上限が人によって
  異なるAPIなら残り担当者の各上下限の和を用いる。
- 区間内コスト、各担当者から始端・終端への接近コストを前計算。
  離脱コストがある場合は向き別の局所コストに含める。
- 例: 6件を3人、各1〜3件で処理するなら、残り1人の段階で前方3〜5件
  以外を探索しない。前の最大終了時刻が12で、順向きの局所時間11、
  逆向き9でも、どちらの最大値も12なので「同点は順向き」を維持する。
- 表は担当者ビット集合×前方長の連続配列とし、復元情報を compact 化する
  のは上限を検証できる場合だけ。状態に過去の向きや退出位置が残る問題では
  その次元を省かない。
- 正しさ: 元DP・小規模全探索で最適値だけでなく復元順と同点規則を照合。
  AHC008は360のキュー照合と400公式ランで全手・得点を照合した。

問題内で実測済み。区間分担の既存実験から共通ライブラリへ適用する提案で、
現時点で既存APIや既定の解を変更しない。
